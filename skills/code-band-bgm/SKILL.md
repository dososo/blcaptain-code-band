# 代码乐团 BGM

由当前Agent理解需求、写新主题与配器，通过本技能`scripts/band.py`驱动本地真实音源。核心不绑定模型厂商、MCP或个人路径，不嵌入收费作曲模型，不把音频上传作为必要步骤。这里是新建的FluidSynth采样乐团；公开版v1不含插件合成器路径。音色文件先用仓库根目录的`scripts/fetch_soundfonts.py`下载。

当前已能生成可编辑谱、演奏事件和真实WAV；**参考同风格创作尚不可作为已验证可用能力，既有独立主音与参考条件基准均已被用户否决**。技术通过、可演奏、参考理解、听感和宿主实测分别记录，不宣传任意歌曲准确拆解或全乐器完整技法。

## 先定位任务

- **实际创作或定向修改**：先读[创作与修订流程](references/创作与修订流程.md)及[操作与契约](references/操作与契约.md)，核已有进度和真实能力。合理默认值直接推进，不把创作变成参数问卷或逐阶段审批。
- **研究、学习新方法或反复失配**：读[音乐知识与决策](references/音乐知识与决策.md)和[参考创作路线选择](references/参考创作路线选择.md)，用`knowledge`选择相关方法。先验证感知能力与音色模型表达上限；不能把静态同族控制、更多规则或模型标签当参考理解通过。
- **主音尚未匹配**：先独立拆解与可演奏音色短样，方向接受前不回乐团、不展开长曲；见下表。参考轨迹重放与演奏新主题不得混报。

## 创作时保持的约定

1. 默认无人声、最终60秒含尾音、PCM WAV 48kHz/24位/双声道；不支持时明确报告，不静默降级。按宿主定位技能根目录；先`doctor`或复用同引擎/同资产能力，再`catalog`查询真实资源。
2. 宿主选用与当前问题相关的少量音乐方法，将“原参考事实／未知／新作选择”分开，写清主句、回应、和声、低音、鼓或纹理的关系。不能用高分标签、更多轨数或大师引文替代音乐判断。
3. 用真实资源、音区、力度层和奏法编写谱；缺项透明替代，不把别的乐器改名。由稳定程序校验、编译时间/资源/随机流、渲染与检查；固定事件允许直接复演，纯混音修改不重抽演奏。
4. 有参考先取得真实本地音频并核具体录音身份；只把可靠抽象特征用于新作，不抄原旋律/切片或用转调当原创。模型结果保候选、残差和反例；没试听不称已听辨。受限链接说明具体阻塞，继续文本/本地路线。
5. 默认一个15—30秒短预览；必要对照最多三个。音乐方向未解决先定位，不反复渲染或展开三分钟。用户反馈用于验收，不能把消融定位直接当删主奏处方。同方法两轮实质修正仍不过，记录失败并换有证据的方法。
6. 每个作品用新目录保存WAV、可编辑谱/编译事件、简报、种子/版本/资产SHA/真实命令清单、检查与使用说明。保父版本和修改证据；“保留旋律”逐事件核差异：增益用`band.py revise`，缩短/循环/加声部用`scripts/score_edit.py shorten|loop|add-part`，再以`score_edit.py diff --preserve`比谱面与冻结事件（含program与采样ID）。改谱不改`score_id`，否则未改声部会换轮换录音。循环周期须为64帧整数倍，48kHz下84 BPM整小节不满足，需换速或换小节数并告知用户。技术、素材和人工听感分列；未试听标“待听感验收”。
7. 文件帧数和全局非静音不证明全时长有音乐。查看`check`的逐秒去直流活动诊断；长低活动区标“需核”。明确要求持续的短样可在检查期望中指定`target_file_frames`及`continuous_tail_max_seconds`启用末端覆盖门禁；结合实际作品的休止、尾音与听感判断。
