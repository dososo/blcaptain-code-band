## 与新版许可的区别

当前官网仓库和新版HF使用CC BY-NC-ND。本项目未取得新版NC-ND音频用于改作，也没有把其许可写成CC BY。官方仓库LICENSE在[2025-09-18提交75ed5ea2](https://github.com/ccmusic-database/ccmusic-database.github.io/commit/75ed5ea20204320ec122f6ba77bde2c2359e3e01)新增，比所依赖旧DOI晚约4年；2021旧README未带这份后期LICENSE。[CC官方FAQ](https://creativecommons.org/faq/#what-if-i-change-my-mind-about-using-a-cc-license)说明已授予的许可不能任意撤回，但这不是对任意不同版本音频的授权。

旧[版本1.1记录5676893](https://zenodo.org/records/5676893)（2021-11-12）同样CC BY 4.0，整体ZIP大小和MD5与1.0不同；本次实际比较了两版同名mf慢音阶，其解压WAV SHA256相同（`46f6239d99befd0cd80270a9713b84902daa18c6f4765b14236957c519acbd44`）。另外三份未与1.1逐字节比较，当前HF新版是否同音频未知，不将其泛称为相同文件。

## 实际修改与演奏边界

3份实录各20个独立持续音：MIDI 57、59、61、62、64、66、67、69、71、73、74、76、78、79、81、83、85、86、88、90。仅开放这些键，不把57–90的包围范围冒充完整半音范围。力度层p=1–55、mf=56–95、f=96–127，来自三次真实录音，区域互斥，未用同份音量缩放冒充新力度。

librosa 0.11.0的pYIN用于稳定音段及音级筛选；原输出有倍频错，保留原始测量，以三次同序上行音阶的音级一致性、逐音局部周期及奇次谐波互证八度与音准。裁取稳定段内部并20ms淡入淡出，不将完整音阶或相邻音变换作单音，不声称保留完整自然吹起音。没有无限延音、循环、RR、滑音、换气、和弦指法或全奏法承诺。

`Sheng-Old-CCBY4-v1.sf2`由固定提交SF2cute写出：单声道16位44.1k原录，制库复制为双单声道PCM16；20根音×3真实力度×2声道共120采样/区域，仅为1件乐器1预设。真实60项逐音、16,256组区域匹配、渲染音准、重复渲染与SF2字节复现已验证，详见`笙验证结果.json`。人工听感仍待验收。

## 从本包重建

复用包内权威源码`build/准备笙.py`和`build/打包.cpp`。先按本包`说明.md`获取固定SF2cute提交`3c5fc83b6ba3d1feb377f9c86021fd77499eb7c0`并编译其静态库，保留本包原文Zlib许可。没有重写SF2格式或采样器。以下命令从项目根执行，`/path/to/sf2cute`改为本地固定源码路径，输出选择新文件，勿覆盖旧资产：

```sh
.venv/bin/python code-band-bgm/assets/chinese-expansion-20261031/build/准备笙.py --work work/笙重建
c++ -std=c++14 -I/path/to/sf2cute/include code-band-bgm/assets/chinese-expansion-20261031/build/打包.cpp /path/to/sf2cute-build/libsf2cute.a -o work/笙重建/打包器
work/笙重建/打包器 work/笙重建/zones.tsv work/笙重建/重建.sf2
.venv/bin/python code-band-bgm/assets/chinese-expansion-20261031/build/验证笙.py --work work/笙重建
```

准备脚本仅用本包冻结测量和原WAV，离线重建不要求再运行pYIN或下载模型。验证命令检查本包正式库；新重建文件先与正式库SHA256比较。平台编译/浮点差异的保证限于已验证本机，其他平台须重新技术验收。
