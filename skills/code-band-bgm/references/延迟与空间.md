# 延迟与空间

已有FluidSynth选定声部混响之外，新增复用[FFmpeg官方aecho](https://ffmpeg.org/ffmpeg-filters.html#aecho)的有限抽头延迟。没有重写DSP，也不下载插件。`doctor`对双声道脉冲实际验证原声、250ms与500ms回声的位置/比例/总帧数，新增可选能力`mixing.delay`；旧能力文件没有这项时，编译含延迟的新谱会明确失败。

乐谱`mix.effects`最多六项：一个可选混响和一个可选原生chorus构成并行前级，两者排列不影响其并行关系；后接一项可选单段EQ、最多两项延迟，最后可有一项显式duck。混响/chorus/延迟的空`target_part_ids`指所有声部，duck必须显式指定非空目标。流程为采样及选定原生混响/chorus并行→单段EQ（配置时）→延迟→duck→声部增益/声像→总线求和。没有总线延迟或自动归一化。示例：

```json
{
  "effect_id": "keyboard_echo",
  "kind": "delay",
  "target_part_ids": ["keys"],
  "parameters": {"delay_ms": 375, "decay": 0.25, "repeats": 2},
  "required": true,
  "notes": "两个有限抽头，分别延迟375/750毫秒，幅度为原声0.25/0.0625。"
}
```

`delay_ms`为1至2000的有限数字；`decay`为0至0.75；`repeats`为1至4的整数，最长抽头不得超过4秒。没有字符串滤镜入口；运行器由数字生成固定参数并通过参数数组执行。它是有限抽头回声，不是无限反馈、乒乓、磁带饱和或自动随BPM变化的延迟。需要节拍同步时由宿主计算毫秒并写入谱中，保留计算依据。

最终帧数保持声明值，尾音包含其中；超出总窗口的回声会明确截断，不补时长，作曲时须预留尾音。循环状态尚未验证，含延迟的循环谱被拒绝。未实现的动态EQ、压缩、限制器仍不能冒称可用。输出峰值超满幅仍失败，不因新效果静默降低音量。

清单保存真实FFmpeg滤镜参数和帧数；FFmpeg版本、采样库和冻结事件都影响复现。无新延迟时旧采样渲染路径不经过FFmpeg处理，本轮旧闭环浮点逐样本摘要复测保持一致。固定事件两次延迟渲染、本机精确重复和脉冲对照属于技术检查，不代表音乐空间、参考风格或人工听感通过。

## 原生立体声合唱

运行器0.3.8复用[FluidSynth原生chorus group API](https://www.fluidsynth.org/api/group__chorus__effect.html)。`doctor`真实渲染同GM005 G4的干/湿/重复探针，验证帧数、有限性、立体变化和同机逐样复现，登记可选`mixing.chorus`。没有已验证能力时编译与冻结重演均拒绝；缺少API或参数读回不符时报错，不静默返回干声。

```json
{
  "effect_id": "keyboard_width",
  "kind": "chorus",
  "target_part_ids": ["keys"],
  "parameters": {"voices": 3, "level": 0.6, "speed_hz": 0.2, "depth_ms": 4.25, "send": 127, "waveform": "sine"},
  "required": true,
  "notes": "同资源的空间表达候选，非原曲效果识别。"
}
```

参数可省略而采用以上固定默认：voices整数1–8、level有限0–1、speed_hz有限0.1–5、depth_ms有限0–20、send整数0–127，首版waveform仅sine。每声部独立合成器，仅指定目标启用；诊断记录实际set/get、MIDI通道与CC93读回。混响与chorus是并行发送，不是先混响再串联chorus。SoundFont可能自带基底发送，`send=0`不一定是干声；零效果对照必须关闭chorus。未配置时保持旧关闭路径。

原生多声部合唱可产生独立左右变化，但不同实现的chorus不一定扩宽，同一side指标也不证明起音、音色或风格匹配；检查单声道折叠，不能用反相追求宽度数字。当前循环LFO状态未验收，含chorus的循环谱明确拒绝。尾声仍包含于总帧长，无自动补时长/归一化。

## 原生声部包络塑形

运行器0.3.1新增可选`part.sound_shaping`，复用[FluidSynth原生发生器API](https://www.fluidsynth.org/api/group__midi__messages.html)，没有另写合成器。`doctor`对主库真实WarmPad60验证三项参数读回、实际音频改变及两次独立渲染一致，输出`performance.sound_shaping`。旧能力未确认该项时，编译和冻结事件重演均拒绝带塑形的新谱。缺省不调用该API，保留旧无塑形音频路径。

```json
{
  "sound_shaping": {
    "amp_attack_offset_timecents": -3600,
    "amp_release_offset_timecents": -2400
  }
}
```

字段仅允许attack偏移[-3600,0]、release偏移[-2400,0]及`filter_cutoff_offset_cents`[-1200,0]。这是相对原预设的SoundFont原生音分单位，不是最终绝对毫秒或Hz；get_gen只读回偏移。当前仅测试代表配置及端点，不表示对所有音源、数值和听感已穷举验证。滤波偏移缺省0，不能默认用降低截止频率解决本已偏暗的声音。

这些是静态声部参数，不支持逐音符自动化、连续808滑音或新采样奏法。缩短合成器包络不能消除原始采样已录入的缓起音；真正需要清晰短音时，应选择并实测合适的真实音源。谱与冻结声部均保存配置，清单登记实际读回值和相关程序摘要；改混音增益不重抽演奏事件。

## 显式事件增益包络

运行器0.3.5新增`duck`。`doctor`做实际浮点控制并记录`mixing.duck`能力，旧能力未确认则拒绝。以下配置按编译后kick的实际帧触发，仅降低sub：

```json
{
  "effect_id": "bass_yield",
  "kind": "duck",
  "target_part_ids": ["sub"],
  "parameters": {"trigger_part_id": "kick", "attack_ms": 4, "hold_ms": 40, "release_ms": 180, "depth_db": -7},
  "required": true,
  "notes": "自有制作选择，非原曲效果参数推断。"
}
```

上述单来源语法的触发声部不能同时是目标；attack为0.5至50毫秒、hold为0至250、release为1至2000、深度为−24至0dB。触发开始后以线性幅度下降、保持、恢复；重叠取较小包络，不相乘。没有音频检测器、阈值、比率、前瞻或压缩器仿真；它不是原曲侧链的识别结果。处理后帧数不变，恢复越过文件末尾时在总窗口截断，循环谱明确拒绝。清单记录触发数、帧参数、最小增益和包络摘要。真实双声部测试核目标改变、触发声部不变及冻结事件不变；听感须另验。

运行器0.3.11允许用`trigger_part_ids`替代上面的`trigger_part_id`，显式绑定1–8个非空、唯一的真实声部ID；两种字段互斥，任何触发声部不能同时是目标。每个声明来源都必须实际有事件，部分来源缺失也失败。编译与冻结重演要求当前`mixing.duck.evidence_ids`含`explicit_duck_multi_trigger`的新探测证据；仅有旧single证据时拒绝，不静默漏掉新鼓。

例如`"trigger_part_ids": ["kick", "kick_body"]`让选位替换后的两套底鼓共同触发同一包络。取所有实际onset的并集、同起去重、重叠仍取最小增益，不叠乘加深；新增诊断保留每个来源的事件数、不同起点数和并集触发数。旧single语法与诊断保持，固定旧谱应单独核音频兼容。`doctor`的纯数组分组/同起重叠控制只证明路由与包络，不宣称原曲压缩器或听感匹配。

## 用户报告爆破音时先做因果定位

无满幅、真峰有余量、冻结可复现均不排除点击、源采样噪声或叠加冲击。先保存被听到的精确版本及试听副本，核副本是否只是常数增益；检查NaN/Inf、满幅、起首/末尾、突变与已冻结on/off。`diff[i]`对应的是第i到i+1帧的变化，报告右侧事件帧应加1，避免声源对齐差一帧。

[Audacity官方Click Removal手册](https://www.audacityteam.org/manual/effects/noise-removal-and-repair/click-removal/)指出过敏处理会伤正常瞬态；[iZotope官方De-click文档](https://help.izotope.com/docs/rx-plug-in-pack/De-click.html)区分窄click、thump与幅度不连续。这里借诊断方法，不以付费工具为依赖。样本差分最大的地方只是候选，不能自动认定是缺陷。

核候选起点附近所有声部，不把最显眼的kick或新加乐器当唯一原因。复用真实数组，或单独演奏该冻结part并与成品诊断峰/RMS核对；在同帧比较各源有符号差分和总和，保留残差/量化差，不把绝对幅度大小直接相加当因果。声部本来连续不等于听感不会爆，噪声鼓音体也不等于数字削波。没有用户位置时可继续独立定位，并保留“候选是否就是所指事件”未知。

只改被定位的事件力度/源或必要增益，检查攻击与鼓身/主旋律分别受何影响；先做局部控制，再核成品，不对全混盲插去click或限制器。当前攻击偏移只允许非正值，不能拿它假称更缓起音；若确需新API范围，先真实探测/校验与回归，不静默接受未知参数。只听诊断性短窗或看峰值都不能签收完整作品已无爆破。

## 单段声部等化器

运行器0.3.12复用FFmpeg `equalizer`二阶peaking滤镜，不重写滤波算法。`doctor`真实测试200/3500Hz双声道频响、脉冲首帧/帧数和固定浮点复现，登记`mixing.eq`及`ffmpeg_peaking_cut_runtime`证据。旧能力未确认时编译/冻结重演拒绝。

```json
{
  "effect_id": "lead_upper_control", "kind": "eq",
  "target_part_ids": ["lead"],
  "parameters": {"frequency_hz": 3500, "q": 0.9, "gain_db": -3.5},
  "required": true, "notes": "仅示例；保留主奏音符/职责，温和减选定泛音带，不是通用去尖处方"
}
```

三个数值须显式给出；频率50–18000Hz且低于当前Nyquist，Q为0.2–8，gain为−12至0dB。目标须非空且唯一，最多一段；双声道f64、mix1、不归一化、blocksize0因果处理，不接受用户滤镜文本。顺序：原生采样与混响/chorus并行→EQ→delay→duck→声部增益/声像。滤波尾包含于原帧数，未验证循环，循环含EQ明确拒绝。没有配置EQ时旧路径不调用FFmpeg，旧音频应单独核逐样保持。

清单记录真实参数数组、输入/输出浮点摘要与FFmpeg版本检查。缺工具、错误输出、错帧或非有限数失败，不返回干声假通过。IIR可能改变相位并令混合峰值略升，不能把减频段叫作限幅。它不提供合成器包络控制，也不保证修好源采样的门内后体抬起/衰减；源音色包络或演奏关系不符仍需独立处理，也不凭高频下降签好听或原风格已懂。
