# 宿主安装与验证

核实日期：2026-10-30。权威源码只有项目内的 `code-band-bgm/`，安装器为宿主建立相对符号链接，不复制创作逻辑，不修改已有 `AGENTS.md`、`CLAUDE.md` 或个人配置。

已阅读的官方资料：

- [Codex：构建技能](https://learn.chatgpt.com/docs/build-skills)：项目入口为 `.agents/skills/<name>/`，支持符号链接；命令行可用 `/skills` 选择或用 `$code-band-bgm` 显式提及，描述匹配时也可自动加载；新增技能未出现时重启宿主。
- [Claude Code：扩展技能](https://code.claude.com/docs/en/skills)：项目入口为 `.claude/skills/<name>/`，支持符号链接；输入 `/code-band-bgm` 显式调用，也可按描述自动加载。首次新建顶层技能目录后可执行 `/reload-skills`。个人同名技能可能优先于项目技能，应在 `/skills` 核对来源。
- [Agent Skills 规范](https://agentskills.io/specification)：通用入口使用 `SKILL.md` 的 `name`、`description`，辅助脚本与资料按需读取。核心不依赖宿主动态变量、权限扩展或专有工具。

在项目根目录运行：

```bash
python3 skills/code-band-bgm/scripts/install_skill.py install --host both --project .
python3 skills/code-band-bgm/scripts/install_skill.py status --host both --project .
```

分别只安装一个宿主时将 `both` 改为 `codex` 或 `claude`。其他项目通过 `--project` 指定目录；`--source` 可显式指定技能源码。安装器要求 Python 3.9 及以上，只用标准库。符号链接受限的系统会报错，不会静默生成另一份源码。

安装会先检查全部目标。同名目录、文件或其他技能链接一律报错并保留；已经指向本技能的链接可重复检查和安装。项目级目录通过链接指向项目外时拒绝修改。若安装失败，已由此次创建的入口逐项撤回；空宿主目录可能保留。

为避免宿主把 `python3` 解析成缺依赖的系统解释器，音乐运行器统一使用项目虚拟环境。首次准备环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r skills/code-band-bgm/requirements.txt
.venv/bin/python skills/code-band-bgm/scripts/band.py doctor --out reports/新能力.json
```

已有 `.venv` 时先检查，不覆盖用户环境；安装Python依赖之外，仍需系统提供FluidSynth和FFmpeg。安装器本身只依赖标准库，可以继续用 `python3`。其他平台使用其对应虚拟环境解释器路径，未经实测不宣称跨系统兼容。

安装后，启动所选宿主并核对来源：

```text
Codex CLI：/skills
Codex CLI：$code-band-bgm 做一首60秒温暖城市夜行BGM，无人声，交付WAV。
Claude Code：/skills
Claude Code：/code-band-bgm 做一首60秒温暖城市夜行BGM，无人声，交付WAV。
```

这些是宿主交互输入，不是终端 shell 命令。桌面端的技能选择界面可能因版本不同而异。单独读到说明不代表拥有代码执行或音频资产权限。

本机版本为 Codex CLI `0.154.0`、Claude Code `2.1.296`。两个项目入口已实际安装并核对指向同一源码；Codex 还通过本地 `app-server` 的 `skills/list` 真实发现了启用的 `code-band-bgm`，证据见 `reports/codex-skills-discovery.json`。这项发现检查没有创建聊天或启动模型回合。运行器已生成 `outputs/音频闭环/v1/final.wav`，最初缺引擎的阻塞已解除。**两宿主均已通过两类独立验收：同一20秒已有乐谱的显式触发、渲染、保留旋律且鼓减4dB；各自从一句中文需求独立创作新主题/乐谱，并交付60秒WAV。两类测试分别留有日志与产物检查，见 `reports/宿主验证.json`。人工听感仍待验收。**

再次复验时，各宿主分别运行并留下文件证据：一句话生成一首60秒作品；对同一作品输入“保留旋律，鼓轻一点”；核对父版本、保留声部事件与最终 WAV 检查结果；提交一个真实参考文件；对受限链接确认如实失败。两个宿主共同使用固定乐谱重渲染，另行比较事件和音频。不要把链接一致或结构校验记为这些行为通过。

移除入口：

```bash
python3 skills/code-band-bgm/scripts/install_skill.py remove --host both --project .
python3 skills/code-band-bgm/scripts/install_skill.py status --host both --project .
```

移除只逐项解除指向当前 `--source` 的符号链接，保留源码、作品和样本；遇到其他同名入口会报错。安装或移除后复查宿主列表，已加载的上下文需按宿主行为刷新。其他 Agent 需要能加载通用技能、读写文件、运行 Python 与音频工具并访问真实引擎资产；本次未验证具体第三方宿主。仅聊天且无本地运行器的客户端不能独立交付本地 WAV。

本地发现无需模型请求的依据见 [Codex应用服务器官方文档](https://learn.chatgpt.com/docs/app-server)。Claude Code 官方 [技能SDK说明](https://code.claude.com/docs/en/agent-sdk/skills)将已加载技能和命令列于 `system/init`，该消息可以在正式受限验收会话中一并保存；本次未找到不发起会话的独立命令行技能列表入口；实际Claude验收会话的 `system/init` 已同时列出目标技能和命令，发现通过有宿主证据。

实际新增原创验收作品为：Codex《锁孔后的微光》位于 `outputs/宿主原创/codex/v1/`，Claude Code《窗边的光》位于 `outputs/宿主原创/claude/v1/`。各目录包含最终WAV、可编辑谱、编译事件、简报、清单和技术检查；作曲数据脚本位于对应 `work/宿主原创/<宿主>/`。二者均为2,880,000帧、48kHz、PCM24、双声道。本机固定谱在两宿主输出的v1/v2分别达到完整WAV字节一致；不推断其他平台。

本次Codex固定谱首轮因默认解释器缺NumPy诚实停止，切换已准备好的项目`.venv`后通过；Claude受限模式拒绝复合命令后改用单条运行器调用。没有绕过权限或安装新收费模型API。两宿主内的参考音频与循环请求仍需分别补测，主工程单独通过不能替代这些宿主场景。
