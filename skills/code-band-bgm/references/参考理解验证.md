# 参考理解验证：先证明解释对应声音

适用：参考音乐创作，尤其已有整体风格否决时。此流程不是参数问卷，也不要求正常创作逐阶段找用户批准；缺口先由Agent用现有工具和音频取证解决。无参考文本创作仍可按默认直接编排。

## 必须区分的能力

|能力|现有工具能给什么|不能由此推出|
|---|---|---|
|取得与身份核验|真实波形、时间窗、哈希/同录音对齐|已听懂音乐|
|专用MIR|拍点、粗分离、起音/音高候选、结构或标签|原preset/完整角色谱与风格已核准|
|音乐语义模型|音乐家族、制作/演奏关系与时间证据候选|流畅回答就是正确；模型大或标榜SOTA便可靠|
|直接音频风格条件生成|在学习到的音频表示上生成波形|已得到解释、原创保证或可编辑的乐团谱|
|代码乐团渲染|按给定乐谱真实演奏、混音和WAV|所给乐谱就是参考风格|

来源证据门禁只检查字段、引用和摘要；`status=通过`及`reference_understanding=证据已记录`不让音乐观察变成真值。v9/v10分别验证了自己的角色/句法计划，仍被用户否决；必须把验证对象转回参考解释与实现的对应关系。

## 先验证方法在听什么

[MuChoMusic原论文与代码](https://github.com/mulab-mir/muchomusic)用经人工核验的音乐问题/干扰选项，并研究音频扰动以检查语言依赖。借其评估思路，不把该benchmark的分数外推为本曲正确。对拟用模型或分析法：

1. 先用有真实已知答案的自有音色/布局控制，配静音、域外音色、相同音频增益、音频交换或时间移动。题目不泄露曲名/作者/期望乐器；不要只问“是不是某乐器”诱发肯定回答。
2. 音色变而布局相同、布局变而音色相同应能被区分；模型应对未知/字典外保留未知。样本同源正控不算泛化，失败原样保留。
3. 对原曲多个代表窗和失败版本保留原始输入/输出、标签表、模型版本/许可、摘要和窗口起点。需要合适的模型/任务，不把tempo工具当音色识别器，也不把模型program当原乐器。
4. 窗口、音区、分离泄漏与增益消融可推翻最初解释。只在对照支持的维度使用结果；不能挑某个更漂亮指标签收。

专用音乐语义模型是有价值路线，例如[NVIDIA Music Flamingo](https://research.nvidia.com/labs/adlr/MF/)处理音乐语义，[All-In-One](https://github.com/mir-aidj/all-in-one)处理拍点/功能段落；它们不是同一种能力。源代码许可与权重许可、论文结果与本机运行分开核；不自动下载巨大权重，不把academic-only/NC权重设为通用默认硬依赖。可选分析器只在明确适用条件下安装。模型仍可能幻觉，不能靠换成另一个captioner解决验证问题。

## 什么证据才可以进入编配选择

先列会改变方案的关键未知，不要求每个原preset都能命名：

- 前景的可辨声音特征是什么：起音/延续/音区、单线或复音、调制/失真/噪声；哪些竞争性解释仍兼容？
- 鼓与低音怎样形成实际重音和推动：哪个频层承重，强弱/留白/切分怎样组织；少量时序数值不能承担整个律动解释。
- 和声触发、内声、装饰与前景的真实关系是什么；从局部统计推断全曲句法的范围有多大？
- 现有资源能否表达这些特征？如果原声音特征不在当前GM/插件/采样字典内，要明确报告不足，不把最相近名称直接标核准。

每个关键决定需“原窗证据→竞争解释/反证→自有载体与演奏→仍未知”。若同一证据同时兼容许多不同风格的实现，就不足以固定FM/弦乐或新和弦。普通包络探针只能证明载体自身行为；它必须回答原窗中的辨别问题，不能拿能发声当匹配。

必要时先做极短的参考诊断再现，明确标为研究材料、不是原创成品、不用原录音拼成新作；用来检验音色/节奏/复音解释是否可再现。不要追求完整逐样复制，也不把参考转录送进默认原创主题。仍无足够对应时停止新曲路线并保存缺口，不再用通用作曲理论补空。

## 创作与验收

只有关键风格差异已得到足以排除错误实现的证据，才另写主题/动机和新谱，最多一个代表短样。是否动听/接近参考还需音乐判断；技术检查、分类标签、相似度或参考诊断通过都不代替人工方向。

[MusicGen-Style官方代码](https://github.com/facebookresearch/audiocraft/blob/896ec7c47f5e5d1e5aa1e4b260c4405328bf009d/docs/MUSICGEN_STYLE.md)展示直接风格音频条件，但输出波形、不输出可编辑逐声部谱；不能配一份无关JSON冒充代码乐团演奏。已有ACE风格条件也不解决这一可解释性缺口。未实际运行的项目记未实测；参数名含reference/chroma不证明它控制的就是所需风格，也不承诺新主题无泄漏。

当用户整体否决时，保留旧作品/原话，撤销该路线音乐认可；下一轮先定位最初未验证的假设。不要继续追加同一套旋律、乐器和乐句“优化”后再次让用户承担盲试成本。
## 持续短样的末端覆盖

当创作简报明确要求16秒持续音乐、允许最多2秒尾音时，可运行 `python scripts/band.py check --input 短样.wav --expected assets/示例/持续短样检查期望.json --out 新检查.json`。原生渲染也可传 `--continuous-tail-max-seconds 2`，在发布作品目录前检查；失败不会发布成品，临时目录保留检查报告。该示例的精确帧数和尾音预算必须按作品修改。门禁以100毫秒去直流窗口、相对于该文件窗口功率75分位的−40dB阈值检查末端，并允许一个窗口量化容差；超预算返回失败。休止、极低动态和其他有意静默可能触发门禁，因此只对明确要求持续音乐的作品启用；它不能判断音乐的风格、好听程度或静尾根因。
