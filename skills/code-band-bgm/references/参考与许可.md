# 参考输入与素材许可

本地文件和公开直接媒体链接经analyze真实解码，记录来源摘要、内容哈希、工具版本、波形测量及低置信候选。速度半拍/倍拍和调性歧义保留；配器、情绪、音乐结构不能仅由频谱可靠确认，标未知或由宿主实际试听后补证据。作者元数据与波形测量分别记录。

## 机器可核验的参考报告分层

`analyze` 的顶层 `status=通过` 只表示取得与本地测量执行成功。新报告同时写入 `analysis_scope=objective_measurements_only`、`measurement_status=通过`、`reference_understanding.status=待语义证据`。它没有声称音频无法理解，也没有声称已理解风格；BPM、调性候选与能量仍可用作有限线索，不能自动签收参考创作。

首次参考新曲的 `render --reference-analysis 分析.json` 会在编译、建立临时作品目录及音频渲染之前检查证据。测量报告可由宿主补充下面的 `reference_understanding` 扩展，其余测量和来源保持原样：

```json
{
  "status": "证据已记录",
  "method": "user_description",
  "source_file_sha256": "与分析报告source.file_sha256完全一致的64位小写摘要",
  "evidence_file": "用户音乐描述.md",
  "evidence_sha256": "该证据文件真实内容的64位小写摘要",
  "dimensions": {
    "timbre_and_space": {
      "observation": "引用实际听辨或用户明确描述的音色与空间特征；未知项明确写未知",
      "implementation": "说明新曲采用哪些现有音色与混响，以及仍有的差异",
      "part_ids": ["melody"]
    },
    "rhythm": {
      "observation": "实际律动依据；不能只填自动BPM候选",
      "implementation": "新曲具体节奏、重音、留白与演奏选择",
      "part_ids": ["melody"]
    },
    "texture": {
      "observation": "实际织体与和声密度依据；无法辨认的和弦不编造",
      "implementation": "新曲声部分工及密度选择，区分观察与创作决策",
      "part_ids": ["melody"]
    },
    "structure_and_mood": {
      "observation": "有证据的情绪走向或片段结构，短片段不能推出全曲曲式",
      "implementation": "新主题发展、段落和收束方案",
      "part_ids": []
    }
  }
}
```

上例是字段说明，摘要占位文字不能通过程序。`evidence_file` 相对分析JSON所在目录解析，也可为绝对路径；文件须可读取且内容摘要一致。程序将证据副本带入作品目录，并将报告路径改为该目录内的相对路径。三个声音维度须引用乐谱中真实存在的声部，结构/情绪维度可使用空数组表示整体编排。

`method` 支持四种来源：`host_audio_perception` 为当前宿主实际音频感知记录；`local_audio_model` 为显式本地音频模型的实际输入与输出记录；`external_audio_model` 为其他独立音频模型记录（保留兼容，不要求云服务，外部上传仍须实际授权）；`user_description` 为用户已明确给出的音乐特征。音乐名称、视频题目、网页文案、Agent自行猜测和只含数值的报告不能冒充这些证据。未确认的维度应保留未知与限制，不能为填齐字段伪造观察。程序仅核对证据链和声部引用，不能验证听辨描述是否真实、质量是否足够，也不保证生成音乐匹配参考。没有证据时补充实际感知或必要的音乐说明；不用重做已完成的音频测量，也不逐阶段要求用户批准。

有本地音频语义环境时可显式调用可选入口：

```bash
.venv/bin/python skills/code-band-bgm/scripts/band.py describe --input 本地参考.m4a --model 已取得的本地模型目录 --out work/本地描述.json
```

`describe` 惰性加载独立模块，普通 `doctor/analyze/render` 不引入其可选依赖；模型目录必填，不由核心自动下载、上传或调用付费服务。模型描述是证据候选，宿主仍需核对来源与限制、填入编排实现映射；模型返回结果不能直接变成人工听感接受。

作品清单、简报及命令结果将 `technical_check`、`reference_understanding`、`style_review` 与 `human_review` 分列。`render` 的 `status=通过` 限于 `status_scope=audio_render_and_technical_checks`，不能作为风格任务完成。默认风格验收为“待人工验收”；证据文件存在且摘要正确也不会自动升级它。

历史作品可以按固定事件重演：只有 `--events` 同目录已有 `manifest.json`、`score.json`、`events.json` 和 `final.wav`，且规范化乐谱/事件摘要与WAV文件摘要均匹配时，才允许保留原来缺少语义证据的版本，标记“历史未核准”。单纯先 `compile` 一份新事件不能绕过首次参考门禁。历史重演不自动重作、不改原文件，已有“需修改/用户否决”状态继续继承；没有可核验交付清单的旧事件不享受这个例外。

## 参考风格核准

### 先绑定用户目标与实际音轨

首次参考创作的分析报告须增加`source.target_binding`：`target_id`为用户给出的文件或具体媒体身份，`input_file_sha256`必须与本次实际测量文件一致。`relationship`仅接受以下三种已核实关系：

- `user_supplied_audio`：用户直接提供的本地文件或直接音频链接；不能将Agent从网页另找的关联音乐冒称用户原文件。
- `target_media_audio`：取得具体媒体实际播放声轨；记录`evidence_file`与`evidence_sha256`；证据JSON内部须有`status=acquired`、同一`target_id`、同一`source_file_sha256`、非空`method`及非空`record`原始取得记录。可将上游原记录原样嵌入record，不要求改写其字段；不保存Cookie或凭据。
- `associated_audio_verified`：网页关联音乐另有同录音时间对齐证据。证据JSON须有`status=matched`、`method=audio_fingerprint_alignment`或`waveform_alignment`、`source_file_sha256`及`target_id`，并绑定`target_file_sha256`和非空`alignment`，每段记录有限非负`source_start_seconds`、`target_start_seconds`及正`duration_seconds`。匹配方法与原始结果应可复核；不能用曲名、标签、CLAP余弦或同宽泛风格代替同录音匹配。

没有绑定或`associated_audio_unverified`会在编译/渲染前失败。`analyze`只知道传入文件，不能自动猜测它与用户网页的关系；宿主按真实取得过程补充绑定，不需要向用户逐阶段请批。网页实际声轨证据随作品复制。程序只核验声明、文件与摘要链，不能证明调用者陈述一定真实；仍需来源审查。历史已交付冻结重演保留原状态，不将旧错误声明升级为新证据。

2026-10-31本项目已实证平台music条目不等于实际播放器声轨：关联片段与实际声轨的同录音匹配尚未建立。自动模型的合理文字、同机可复现和四维字段完整都不能补上这一缺口。

先确定具体视频和片段。搜索词、弹出视频ID、标题不一致且目标存在歧义时，澄清目标，不能把进度告知当作确认。

创作简报记录音色/空间质感、节奏/律动、和声/织体密度、情绪/结构的可靠依据及新曲对应方式。BPM相近、调性相同或整轨能量相似不能单独证明同风格。混有解说的音轨测量可能主要反映讲话，不能据此自选钢琴/吉他编制并称完成风格参考。

没有音频感知能力时明确说明，可以继续识别原曲及核实可靠风格信息；缺少必要依据则澄清，不盲渲染。上传参考到外部模型仍须符合原有授权，不能因需要听辨而默认上传。技术验收和风格验收分列；用户否决风格时保留文件、记录“需修改”，不把WAV技术通过写成音乐任务完成。

本地模型证据须直接提供`describe`的原始JSON报告，`analysis_scope=local_audio_language_model_estimates`，内部`source.file_sha256`与本次参考测量相同，并有完成的片段描述。仅改外围摘要、套一层人工包装或引用另一录音的模型报告不能通过首次参考门禁。人工交叉说明可另存，不能取代原始报告；已交付历史的旧包装只允许以“历史未核准”重演，不升级为风格通过。

公开链接只支持直接媒体，不抓网页播放器，不读取cookie，不绕登录/付费/DRM。默认direct模式验证公网IP，拒绝内网、凭据URL、过大下载、超时和间接播放列表。部分系统代理将公网域名解析到保留网段，会被明确阻止；可使用合法本地文件路线，或显式选择下面的已实现代理方式。URL查询参数不会公开落清单。

```bash
.venv/bin/python skills/code-band-bgm/scripts/band.py analyze --input '公开HTTPS音频地址' --network-mode system_proxy --out work/链接分析.json
```

system_proxy仅使用操作者信任的已配置HTTPS代理，不修改系统设置，不读取Cookie或额外凭据，不自动从direct降级。只接受HTTPS/443，拒绝凭据URL、本地名、私有IP字面量、NO_PROXY绕过与不安全跳转，并保留证书验证和预算。代理后真实目的IP无法验证，此模式不能被描述为与严格直连的公网IP校验等价。当前项目已用作者官网MP3实际验证，下载内容与合法本地参考哈希一致；该功能不表示任意网页或受限歌曲都可取得。

默认不上云，不复用原录音切片，不把转录音符传入新曲。宿主应将真实分析整理为抽象风格简报，再独立写新主题；可以保留源文件供人工复核，不能宣称相似性指标保证完全原创。翻奏/改编请求必须单独标注并另建契约版本，不能冒充默认独立新曲。

音色为MuseScore官方托管的MuseScore_General 0.2，MIT许可原文及逐预设来源CSV随assets/soundfonts保留，来源链见项目开源方案调研。该库由成熟采样引擎演奏，不是简单正弦替代声称原视频音色。FluidSynth动态库为LGPL；本技能只调用系统安装库，不重新发布修改后的引擎。Python依赖分别保留其上游许可。

逐曲交付应保留参考来源、录音许可/署名依据、参考哈希及实际分析。不因曲谱已属公有领域推断现代录音也自由。没有参考许可只阻塞相关参考任务，不阻塞无参考创作。

成熟节拍后端可在安装`requirements-rhythm-analysis.txt`的隔离环境调用`analyze --rhythm-backend librosa`。它复用librosa0.11.0的HPSS/起音/动态规划节拍，最多三个30秒窗，保留真实起点和逐拍候选；不估拍号/摇摆、不把半倍拍歧义抹去，不因三个窗一致就宣称听感已验。缺依赖明确失败，基础候选和成熟后端分别记录，不悄悄降级。

另有可选`beat_this`后端，要求显式本地checkpoint及SHA，CPU FP32输出全输入范围拍点/强拍，见[拍感与角色核对](拍感与角色核对.md)。原始间隔可能漏拍/半倍，不能机械统计唯一速度；不把输出数组当音乐语义证据，原有目标绑定与四维门禁仍保留。模型代码/权重、训练素材和用户参考录音分别核许可；不捆绑用户原曲或局部分离估计组作为公开示例。
