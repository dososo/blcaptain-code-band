## 机器字段与接口

权威数据位于 `assets/instrument-catalog.json`，每条用 `instrument_id` 标识概念，用 `resource_id` 和 `available_resource_ids` 标识实际运行器资源，二者不能混用。主要字段为：

| 字段 | 含义 |
|---|---|
| `name_zh` / `aliases_zh` | 中文名称与可查询别名 |
| `family_id` / `sound_production` | 编制家族与发声分类 |
| `availability` | 可用边界，不是听感评级 |
| `resource_id` / `available_resource_ids` | 首选与其他已注册资源；缺口为null/空数组 |
| `resource_pitch_ranges` | 每个真实资源允许的键域 |
| `required_hit_keys` / `required_hit_notes` | 单件打击必需的逻辑键名及确切MIDI号 |
| `prototype_resource_id` / `pitch_range` | 有限原型绑定及其范围 |
| `full_instrument_coverage` | 原型是否仍缺完整能力；partial条目固定missing |
| `source_refs` | 名称/分类一手来源ID；不是采样许可 |
| `sampling_gaps` / `prototype_limitations` | 明确缺失的演奏与采样能力 |
| `not_equivalent_to` | 禁止混同的目录概念 |

宿主无关接口：

```python
from instrument_catalog import query_catalog, validate_catalog
validate_catalog()
query_catalog('古筝')
query_catalog('古筝', 'reports/engine-capabilities-expansion-20261031-v9.json')
query_catalog()  # 返回完整目录与总览
```

`query_catalog(query='', capabilities_path=None)` 只按名称、别名、概念ID和家族查找，精确名称优先，不把说明文字中的“不是长笛”当成长笛匹配。参数保持普通文本，不拼成shell命令。查询不会下载、替换、演奏或安装音色。目录里的 `runtime_verification` 是历史说明，本次实际状态单独在每个匹配的 `runtime` 中返回。

未传能力文件时，`runtime.runtime_verified=false`。传入能力文件后，先复用 `score_tools.validate_capabilities` 检查结构、证据引用及 `resource_manifest_sha256`，再核对已探测状态、离线渲染证据、资源ID、bank/program、当前音色文件SHA256、能力键域与所需逻辑鼓键。非法顶层类型、损坏摘要和未探测却宣称已支持的报告返回结构化错误。通过仅说明“所提供能力报告中有代表音证据且资产/绑定一致”，不会把partial升级，也不证明能力JSON的制作方可信或全音域可演奏。能力报告来源必须可信；查询不是重新运行doctor。

项目CLI由统一入口提供 `catalog --query` 与可选 `--capabilities` 参数；CLI挂接与本模块分开验证。

- [教育部教育百科四胡词条](https://pedia.cloud.edu.tw/Entry/Detail/?search=%E5%9B%9B%E8%83%A1&title=%E5%9B%9B%E8%83%A1)：只用四胡名称与擦弦类别事实，不复制受禁止改作条款限制的整段释文。
- [河南博物院王孙诰编磬馆藏](https://www.chnmus.net/ydgyt/collection/details.html?id=7100008785220997120)：编磬的实物、名称与按石片定音的打击乐器属性。

- [MIDI协会GM1规范说明](https://midi.org/general-midi-level-1)：标准规定声音名称与键位，不规定声学真实性；官网旧PDF链接404，具体键位另用上列MuseScore官方托管表。
- [拉丁打击乐原厂库伊卡资料](https://www.lpmusic.com/products/lp3408-8-cuica/)：巴西摩擦鼓的结构与压膜变音方式；GM的78/79两采样不等于连续控制模型。

## 双录音预设的确定性轮换

当已登记资源明确具有两份独立录音（当前仅VCSL卡洪、框鼓和姆比拉的RR1/RR2预设）时，可用统一入口生成可编辑新谱和冻结事件：

```sh
python scripts/band.py rotate-samples --score 原谱.json --events 原生冻结事件.json --part 声部ID \
  --resources vcsl_cajon_rr1 vcsl_cajon_rr2 --capabilities 能力.json \
  --soundfont-packs assets/soundfont-packs.json --out 新目录
```

输出`score.json`、`events.json`、`rotation.json`；用现有 `render --score 新目录/score.json --events 新目录/events.json --change 新目录/rotation.json` 与相同能力和音色库渲染。固定主种子和声部得出轮换起点，再交替已核验不同样本，其他声部的已编译事件及其随机流保持。原声部拆为两个预设声部，原note_id和音乐时序保持，event_id会变化；乐谱和变更文件必须一起保存。

此实现拒绝目标声部启用人性化、参与效果目标或触发、循环、非空外部控制、合奏封套、未登记配对、音区无采样及两预设引用同一采样的情况。原生冻结事件须与当前谱、资产及确定性编译严格一致，避免丢失已解析演奏。它不是SoundFont预设内部任意zone的轮换，也不代表演奏法、循环边界或人工听感已验证。
