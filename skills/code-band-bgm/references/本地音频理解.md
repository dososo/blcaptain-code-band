# 本地音频理解

当前固定窗口、窄任务与候选主张接口见[本地音乐语义审查](本地音乐语义审查.md)。以下`describe`保留历史兼容；其正常返回、泛描述或与数值测量并列不能自动核准参考音乐风格。

数值测量与声音语义是两步。`analyze`检查真实音频并给出低置信速度、调性和能量；`describe`调用显式安装的本地音频语言模型描述声音。两者均不足以自动核准配器；关键角色经有判别力的对照后，宿主才形成参考新曲简报和资源映射。模型描述仍是估计，不能代替用户听感接受，也不能保证全乐器识别正确。

本地适配器复用MLX-Audio，当前验证目标为Apple Silicon上的Qwen2-Audio架构。普通作曲与渲染不需要模型；参考理解依赖必须在安装时明确告知。其他系统的语义适配器尚未实测，不能称为任意平台即装即用。核心不要求某家模型API、MCP或外部上传。

## 安装与调用

在项目内另建环境，不改原渲染环境。将下列路径换成自己的目录。

```bash
python3 -m venv .venv-audio
.venv-audio/bin/python -m pip install -r skills/code-band-bgm/requirements.txt -r skills/code-band-bgm/requirements-audio-understanding.txt
.venv-audio/bin/hf download mlx-community/Qwen2-Audio-7B-Instruct-4bit --revision c65570002626f41b4dc08b7b54f42f99f3e82e7f --local-dir assets/local-audio-model
.venv-audio/bin/python skills/code-band-bgm/scripts/band.py describe --input 本地参考.m4a --model assets/local-audio-model --out work/声音描述.json
```

公开模型实际总大小为6,574,659,991字节；核心权重SHA-256为`0967cde270ad62aa4824f0bbce283d0a2a6da2825ccf587640753c527d4174da`。下载只是取得公开权重，不上传音频；安装后描述命令强制离线并只接受本地文件和模型目录。模型权重不随技能压缩包重复分发。

模型为Apache-2.0，MLX-Audio为MIT，其他运行依赖分别遵循上游许可。量化模型来自MLX社区，原模型来自Qwen；完整来源与限制应随安装/分析清单保留。下载说明不是运行通过证据，实际状态见项目验收记录。

## 分析范围与兼容修正

短于30秒的文件读取完整片段；更长文件取头、中、尾最多三个30秒窗口，记录真实位置及解码数据摘要，不能声称分析了未覆盖部分。输入上限为600秒，原录音不参与新曲混音。

MLX-Audio 0.6.3的Qwen2-Audio前处理使用HTK滤波，和原模型官方Whisper的Slaney滤波存在实测差异。适配器复用本地处理器的官方特征提取，验证形状为`1×128×3000`；不修改第三方安装包。2026-10-31新增有效长度修复：按官方特征掩码计算卷积与池化长度，编码注意力屏蔽补齐帧，仅把有效音频token送入语言模型。报告标记`backend.adapter_revision=qwen2_audio_valid_frames_v2`。

本地明确中文讲话的同题对照从“没有讲话”恢复到准确转写，5秒钢琴从“木头摩擦”恢复到音乐类别，证明旧路径存在实际输入问题。纯音仍被虚构成人声、直接绕过静音门禁的模型仍描述出音乐，不能宣称音乐识别全面可靠。生产命令会拒绝全部静音窗口；这不是模型本身认识静音。旧版未屏蔽补齐段的描述不得沿用作新作品的可靠风格依据，保留为历史证据。

尚未证明量化MLX与原生Transformers数值一致。每个新环境先用自有、明确内容的语音与乐器对照检验，再分析参考；模型主奏/空间判断矛盾或与测量冲突时保留未知。模型声称的精确速度、调性、音源品牌须另有测量或来源支持。

描述报告保留模型/配置/权重摘要、依赖版本、固定种子、提示词、窗口与原始模型回复。宿主应把其与真实测量交叉核对，再按[参考与许可](参考与许可.md)补齐证据和四维编排映射。模型表达含糊或互相冲突时保留未知，不能强行绑定某种主乐器。
