# 拍感、角色与风格返工

参考节奏不清或用户否决风格时按需读取。用户明确的情绪、用途、认可维度是目标依据；小调、速度、响度或模型情绪词不能覆盖它。先固定实际音频SHA、裁切区间及解码时间轴。平台关联音乐须另有同录音证据；保留旧作品与否决状态。

## 分开观察、解释与创作

分别核拍点/重音、前景发音与句尾、支撑/回应功能、低频与鼓、音域与空间。只为具体问题局部分离。drums/bass/other/vocals都是估计组，other不是独立主旋律；NMF分量不是乐器，混音中的YIN/起音不是可靠逐音转录。保留原始模型回复、警告、置信理由与未知，不以数值有限替代音乐解释。

每项记录可测事实、带限制的解释、显式创作选择及证据时间。家族不确定时可以提出可撤回试奏，不能称原preset已识别。新主题/和声/节奏另写，不将参考录音或转录直接送入原创模板。

## 可选本地BeatThis拍点

普通渲染和基础测量不需要此模型。独立环境可安装`requirements-beat-this.txt`，它会引入PyTorch/torchaudio等依赖；按目标平台准备CPU环境，不据本机宣传所有平台。已验证beat-this1.1.0、rotary0.9.1、PyTorch/torchaudio2.9.1，显式CPU FP32、4线程、无DBN/madmom。核心不下载模型或切换GPU。

[官方README](https://github.com/CPJKU/beat_this)声明代码与公布权重MIT，并提示训练音频权利范围各异。模型由使用者从官方指定来源显式取得，核版本与摘要，不采用来源不明镜像。已实测官方final0为81,058,141字节，SHA256如下。

从技能根目录运行，替换本地文件路径；Agent使用参数数组：

```bash
python3 scripts/band.py analyze --input 用户参考.mp3 --rhythm-backend beat_this --rhythm-model 本地模型/final0.ckpt --rhythm-model-sha256 8c328b45f59d8dd3dff219253ff6a8d6482be57d0133a29140e2febbf8eb8331 --out 新拍点分析.json
```

必需本地普通模型文件和期望SHA；对同一打开句柄完成摘要校验及官方加载，路径变化不会触发上游短名下载。缺依赖、错摘要/输入/输出时失败，不悄悄回退。模型参数用于其他后端也明确拒绝，不能静默忽略。

`rhythm_analysis`包含原始`beats_seconds`/`downbeats_seconds`、观察范围、CPU/版本/模型SHA。时间相对本次解码输入起点；输入为裁片时另存原曲绝对起点。接口范围5—600秒，本机实际验证含约190秒参考；上限不是性能保证。

模型会漏拍或切换半倍/倍拍，不能将原始拍数或间隔中位数签收为唯一速度。强拍由官方后处理吸附最近拍点；50Hz量化不等于鼓起音精度。拍号/鼓件可保留未知，慢拍2/4与快拍第三拍可能等价。结合周期、稳定窗及重音分布解释，不以高sigmoid声称正确率。

## 音源与代表短样

先查真实资源及能力，再选包络、音域和功能。最多少量固定2—3秒音源探针检查起音、释音、频谱和重复性；它们不是多首作品候选。插件须保存并读回权威完整state，宿主旋钮写入成功不证明实际生效；预设内置效果与外部效果分开。

Schema或某库有参数名字不等于引擎已实现。侧链/自动化有需要才先验能力；用写出的音符空隙让位时如实说明。空间宽度不能唯一证明chorus，包络重复不能唯一证明delay，不照搬旧回声时间。

一个15—30秒原创代表预览直接展示主体、主次、句尾与变化。丰富度来自动机、音域、和声、呼应及进退，不按乐器名计分。参考与候选取相近功能片段、同长度，用透明常数增益匹配响度并保留参数；比较过程不偷偷EQ、压缩、限幅。描述符/嵌入不等于好听概率。

普通授权工作不逐阶段请批。连续否决的风格问题先核一个可播放短样，再展开长曲；技术不能替用户审美签收。保留认可维度、原话与失败状态，同法最多2轮仍失败则记录证据后换方法。没有实际听辨或用户反馈时保持待验，不把新短样自动升级风格通过。
