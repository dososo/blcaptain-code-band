# 合奏、乐器家族与段落分析

适用：识别参考中的乐队/多乐器配合、层次/情绪/空间变化、回应和间奏。不能只听一窗或取一个最高标签，再把全曲写成一种音色。当前能交付可追溯的多标签候选、分离估计与跨段职责图；不能宣传已经可靠认全任意录音的乐器。

## 把四件事分开

1. **估计源类别**：`separate-reference`的piano/guitar等是模型分配，不是原工程分轨。一个类别可含多个真实源；低能轨/大残差须保留，不能把弱轨拉满认琴。
2. **乐器家族候选**：`analyze-instruments`保留同窗多个标签及原始分数、控制反证；不取top1、不做互斥softmax，不把分数叫存在概率。键类/拨弦/合成类可能混淆，不能直接绑定唯一GM或民族乐器。
3. **演奏职责**：主主题、节奏和声、持续载体、低音、低冲击、中高重音、细节、回应/装饰可以由一个或多个音源承担。分别观察起音/延续、音区、复音、重触发、主从与让位；记谱轨数不等听觉层数。
4. **段落与表达**：按有证据的变化选窗，比较进入/退出、主从交接、频段/包络与双声道空间。情绪/间奏角色先记假说和未知，用户目标与新作意图单列；低能量、小调或标签不自动等于悲伤。

单声道分类器不能判断原立体声像。空间用原双声道测量，区分左右电平、相关性/旁能量、干湿、起音和释音；不能只用加chorus或更多轨数代表多层次。含强残差的分离段必须同时审查原mix与残差，不能只盯命名轨。

## 可执行的本地候选入口

可选后端复用[PANNs官方实现](https://github.com/qiuqiangkong/audioset_tagging_cnn/tree/d2f4b8c18eab44737fcc0de1248ae21eb43f6aa4)。固定官方代码/标签随`assets/vendor/panns-cnn10/`保留原MIT许可，未重写网络。唯一已验证权重为作者[Zenodo发布](https://zenodo.org/records/3987831)的`Cnn10_mAP=0.380.pth`；发布API元数据声明CC BY 4.0，需保留作者、来源、许可与变更说明。它的527项是**音频类别**，不是527种乐器；标签覆盖不完整，不能据通用Flute/Zither直接确认笛子/古筝等细类。

模型大小25,237,595字节，SHA256：

```text
5240bdc47444e331bbeb54fd741d2b3f933a4526e84b0c17bf3593df94b13962
```

默认音乐渲染无需本模型。操作者显式取得权重，另建可选环境，避免修改主环境：

```sh
python3.12 -m venv .venv-instruments
.venv-instruments/bin/python -m pip install -r skills/code-band-bgm/requirements-instruments.txt
.venv-instruments/bin/python -m pip install --no-deps --target 本地候选资产/隔离依赖 torchlibrosa==0.1.0
```

这些是安装步骤，不代表在所有系统实测；本机macOS/Apple Silicon实际使用已有隔离Python和单独target，未重建用户环境。权重不随普通分析命令下载，缺失/摘要错误/版本不符明确失败。当前候选worker依赖Unix的`resource`模块，Windows不能直接运行这条可选后端，需另作适配；默认采样渲染与此可选后端分开。

登记与使用（模型路径、隔离Python和输出均由操作者选择）：

```sh
python skills/code-band-bgm/scripts/register_instrument_backend.py \
  --checkpoint 本地候选资产/Cnn10_mAP=0.380.pth \
  --source-root skills/code-band-bgm/assets/vendor/panns-cnn10 \
  --dependency-root 本地候选资产/隔离依赖 \
  --backend-python .venv-instruments/bin/python --out 本地候选资产/后端配置.json

python skills/code-band-bgm/scripts/band.py analyze-instruments \
  --input 本地参考.wav --model-config 本地候选资产/后端配置.json \
  --backend-python .venv-instruments/bin/python \
  --window-plan 分窗计划.json --out 新候选目录
```

分窗计划由宿主按真实变化编写，来源摘要必须匹配；不要等间距抽样后把每窗命名成副歌：

```json
{
  "source_sha256": "实际输入音频的小写SHA256",
  "windows": [
    {"window_id": "main", "start_seconds": 60, "duration_seconds": 8},
    {"window_id": "contrast", "start_seconds": 94, "duration_seconds": 8.5}
  ]
}
```

最多8窗、每窗0.5–30秒、合计不超过120秒。程序准备精确32kHz单声道FLOAT分析副本，再由独立CPU进程一次严格载入60个state键，以固定32k/1024FFT/320hop/64mel/50–14000Hz前端运行；CPU两线程、FP32、batch1，禁网/禁下载后备，后端3GiB/300秒，父进程330秒。源码/标签、权重、版本、target依赖、worker、原始报告、源与计划/窗口摘要都保留；私有空pycache前缀避免读旧字节码。失败留`.instruments-*`证据，不发布假成功；输出目录拒绝覆盖。

`analysis.json`保留所有527标签/每窗527分数和原始报告引用，`composition_ready=false`、`physical_identity_confirmed=false`。分数不按0.5一刀切，不把较小值当绝对不存在。已知控制显示FM可能被打成拨弦/吉他、静音仍有Music残分、同一合奏减增益会改变分数与排序；必须随解释保留。模型输出不能自动给原乐器身份、情绪、准确源数或风格盖章。

## 交给宿主的合奏职责图

按实际观察窗保存源SHA、时间基准与证据引用；每个角色允许多个家族候选，一个家族也可承担多个角色，物理源数允许未知。建议保存：

- 各窗：原始家族标签分数、估计类别与残差、音区/发声特征、空间观察、已支持/候选/未知。
- 各层：音乐职责、候选载体及反证、活动窗、进入/退出、与其他层的让位/交接；不把泛音或同刻加倍直接称第二旋律。
- 各段：结构角色与情绪假说、支持窗、未观察区间；新作的段落情绪目标另列，不能冒充原曲事实。
- 新作实现：对应的真实资源/音区/奏法/时序/空间链和替代限制；许可与模型标签分开。

可将这些小报告放入`local_role_analysis`证据包，见[本地分离与角色证据](本地分离与角色证据.md)。打包小报告不自动复制它们所引用的参考音频、原始NPZ或模型；重跑分析仍需原资产。来源/结构校验不证明观察真实。

## 把研究落实到乐队演奏

[GrooVAE官方方法](https://magenta.tensorflow.org/groovae)把击打图案与力度/微时序分开。先核缺失的近邻击发和各鼓件职责，再考虑细微表情；随机humanize不能补回漏写的连拍。[DeSantis官方编曲书](https://cdn-resources.ableton.com/resources/uploads/makingmusic/MakingMusic_DennisDeSantis.pdf)提供前中背景、互补运动和音色交接的写作方法：一句移动时另一层维持，回应取得注意力时主句让位；这些策略不是原曲的乐器证明。

需要补音色时按职责选择真实资源，允许有根据的多承载，不把“别乱加乐器”固化成只许一个GM。对“缺旋律”还需核主题轮廓、目标音、句间标点、可辨重现和回应，不能仅添加更多和弦音。新声部若全程齐起/常驻、没有交接，或慢起长尾抹掉主句，就否决该实现。

连拍先检查当前引擎同pitch门控与真实采样释音。经具体音色控制支持后再选gate或交替发声；不能全局放宽同音重叠、截短所有鼓尾或将低音周期当新kick。当前一次局部控制支持TR808 kick约160ms gate演奏267ms近邻、clap约80ms/snare约60ms gate演奏133ms近邻；仅这组参数/资源实测，非所有鼓通用保证。

最后做一个短样的实际solo/mute、交接/尾音和全mix检查，再听节奏、主题、层次与空间。技术、素材/创作审查和人工风格分别记录；未获音乐方向接受不展开长曲，不将模型排名或乐器数量当听感验收。

## 被反馈“单一、单薄”后的判别实验

先让解释能排除错误实现，再写下一个短样。复用[Native Instruments互补叠层方法](https://www.native-instruments.com/blogs/blog/how-to-layer-leads)中的频率、包络与空间分工；这是制作方法，不代表本参考用了其产品或特定音色。

- **宽度在哪一层**：用`audit-reference`的分频能量与`band_side_energy_fractions`一起查。总side相近可能掩盖高频几乎mono、中频却已很宽的差异；不要继续给全部键盘加chorus，也不要用反相追指标。
- **稀疏还是短尾**：对原mix、估计轨与残差比较多拍位活动、能量集中度和局部衰减。整窗高频覆盖低，不证明每个打击尾音都太短；若单击相近而活动分布不同，应改短击位置、弱击/重击和少数延展音体。开镲、shaker等只可作为经真实试奏的实现选择，不能倒推原鼓件。
- **复音与泛音分开**：单音弦乐可以比三音近正弦有更多谱峰。检查同时MIDI、实际各基频保留、包络和稳定持音；谱峰数、声部数及合唱voice数均不是原乐器数。
- **持续与短击分开**：若证据支持连续有调底层与密集短触发，至少用一组稳定内声跨越多次短击作机制实验；和声变化点单列，短击顶声可运动，不能每次击发都把整组内声重置。它是可证伪组织方案，不是识别出原谱。
- **对照保持变量边界**：同音区/力度/和弦的音源控制只隔离载体；全曲音区、力度、活动比例改变后，不能把频谱变化全归给换preset。换Grand、增加暗pad或多一种吉他均不能直接签收。

[FluCoMa官方NMF示例](https://learn.flucoma.org/learn/bufnmf/)利用频谱成分共现分解鼓声，同时明确算法不知道人如何感知独立声源，且分量数由操作者指定。不要把NMF分出三块当三件真实乐器，也不要因可相加重构就宣称分离身份正确。分离谱的能量贡献相加须处理互相关；简单相加各轨RMS平方不能代替全mix。保留反证后，才把支持的职责写进真实音源、时序与效果路由。

## 舒展、情绪与声音展开

用户认可节奏而仍指出音色/情绪和声音展开不足时，保认可的事件关系，重新核主奏音体与声场随时间的变化。比较前体、门内后体、释音的分频Mid/Side绝对能量及相对份额，并与原mix交叉；中声退得更快可使侧份额升高，即使侧声本身也在衰减。不能把“散开”直接翻译成全频加宽、更多chorus或更长混响，既有源已经过宽/后抬时可能更偏离。

改变承载不等删除音乐职责。必要时可将已解析主句完整迁到另一真实后端，逐帧保onset/gate/pitch/velocity与源ID映射，保其他族和已认可前体；不得重新做拍秒换算或默认全线叠旧主奏。原后端专属EQ/空间不能假称跨到新插件。新载体先独立演奏同完整主句，以一次显式角色电平对齐控制响度差，再到完整合奏验证，不凭独奏更响签宏大。音色含低八度/submix时注明，检查与既有中低层的职责；MIDI力度保留不自动等同原VCA动态。

第三方patch名称/分类不能充当实际声学或物理乐器身份。须核实际state、复音、发音和新实例重复；若起相随机，先查官方适用版本实现，再保存有明确全部差异的新state。[Surge 1.3手册](https://surge-synthesizer.github.io/manual-xt/)说明Retrigger会固定起相且改变前体一致性，并非无损保原音色。参数缓存setter可能连带改变无关字段，必须读回完整原生state比较，不能放宽摘要门禁。固定起相、更多异频齐奏、响度或立体声读数均不签有灵魂/自然/原曲风格，最终短样听感仍单列。
