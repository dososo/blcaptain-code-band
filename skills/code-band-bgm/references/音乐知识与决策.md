# 音乐知识与决策

这是一套带证据和适用条件的方法库，帮助宿主把作曲、配器和声音分析变成具体动作。它不是新训练的音乐模型，不会因收录名校、论文或获奖作品就自动获得听觉能力。当前参考同风格创作仍未通过人工音乐验收。

## 先选问题，再读方法

在技能根目录运行；Python应使用项目已配置环境。无需新增模型、向量库或网络服务。

```sh
python scripts/band.py knowledge
python scripts/band.py knowledge --topic 参考理解 --topic 音色重建
python scripts/band.py knowledge --topic 旋律与和声 --topic 配器与层次
python scripts/band.py knowledge --rule MR03 --out 新研究决策.json
```

无参数只返回索引；多个主题/规则取并集、按原顺序去重；未知ID明确失败；输出文件不覆盖。结果包含方法库SHA、规则的适用域/动作/反例/项目落点/验证方式及其引用来源。`status_scope=knowledge_selection`只表示资料选择成功，不能升级成能力或作品通过。

唯一权威数据在`assets/knowledge/音乐方法库.json`。不让两个宿主各维护一份创作逻辑；Codex与Claude Code都读取这份数据。来源条目保留“摘要已读”“正文已读”“源码核读”“历史实测”“本轮运行”的差别。需要复核版本时再访问原链接；离线使用现有快照日期，不把它伪装成最新。

| 当前问题 | 按需主题 | 要落实到工程的决定 |
|---|---|---|
| 一句话创作、时长和用途 | 需求与曲式 | 主句/段落职责、结构预算与包含尾音的帧数 |
| 点头拍感、连续推动 | 节奏与律动 | 鼓、低音、有调短击的复合节奏和重心 |
| 主曲单调、没有发展 | 旋律与和声 | 可回认动机、节奏变形、目标音、和声变化速率 |
| 轨道很多却单薄 | 配器与层次 | 同时融合、独立声流、接力、进退与必要加倍 |
| 民族或西洋乐器组合 | 中西乐器 | 音乐语境、实音/移调、物理技法与真实资产交集 |
| 刺亮、机械、长音无表情 | 演奏与音色 | 起音/持续/释放、奏法、力度层、轮换和实际控制响应 |
| 混合录音或现场片段 | 参考理解 | 身份/窗口/语音和环境干扰、候选角色、竞争解释 |
| 主音不像、需演奏新主题 | 音色重建 | 多音分组、音体与空间分开、共享参数与真留出 |
| 浑厚、宏大、散开但不糊 | 混音与空间 | 频层和角色的前后景、低频职责、效果时序 |
| 新后端、DAW、样本与模型 | 工具与许可 | 具体版本、代码/权重/音色许可、资源预算、接入状态 |
| 指标绿但音乐不对 | 验收与复现 | 真源控制、等响度试听、固定事件复演、人工方向 |

通常一次只取与当前缺口相关的两三个主题。不要为一首歌重读整个库，也不要把所有规则同时套到所有风格。

## 把方法转成音乐决定

每次关键改动在作品目录记录下面六项即可，不要求用户填写问卷：

1. **目标和保留项**：用户要什么体验，哪些维度已认可，哪些仍被否决；没有参考时用明确创作意图，不伪造分析。
2. **事实、未知、自选方案**：原曲实际观测与模型候选分开；原器未知时允许保持未知。新曲的调式、音源和空间设计标为创作选择。
3. **职责与关系**：主线、回应、和声、低音、鼓或纹理在何时独立、融合、交接；每条线用事件/声部ID关联，不靠轨名证明效果。
4. **使用的方法**：列选中的规则ID、来源ID、为什么适用，以及哪个反例可能推翻它。
5. **可执行动作**：真实资源ID、音区/奏法、谱或事件差异、效果与混音变化。资源和控制不支持的动作应改写或列缺口，不能生成无效CC假装已执行。
6. **检查与结果**：预先说清比较哪一个假设、保持哪些条件、看什么证据；技术、分析可信度、音色、音乐方向分别记录。没有人试听就保留“待听感验收”。

“资料推荐”不是确认提示：资料足以支持且用户已授权时，继续可逆工作。不要用方法库制造逐步审批，也不要把用户的小白听感转换成未经验证的删轨处方。

## 当前推荐的技术组合

| 层 | 现在复用 | 能做什么 | 还不能据此保证什么 |
|---|---|---|---|
| 音乐写作 | 宿主Agent＋公开乐理/作者方法；可选music21 | 写新动机，核音程和声部关系，记录发展与职责 | 自动拥有审美或准确识别混音原器 |
| 参考观察 | 已有节拍、Demucs、YourMT3、PANNs、CLAP局部适配 | 真实固定窗测量、源/家族/音符候选及负控 | 任意现场、多源电子主奏的完整真值 |
| 主音研究 | SMS谱观察＋Surge完整状态；两帧静态音体限诊断 | 局部观察、共享参数、新MIDI演奏 | 两帧模型代表任意复合主奏；该默认重建路线已被v31反例否定 |
| 音频方法基准 | 可选本地ACE参考条件及官方分阶段实现 | 单16秒波形研究已实际运行，现场条件可审 | 可编辑乐谱、逐音保持、原器识别或音乐通过；尚非通用正式后端 |
| 实际演奏 | 已登记FluidSynth样本＋Surge＋统一事件/渲染 | 本地离线WAV、已支持的混音和可复演事件 | 普通音色自动具备连奏、滑音、多力度实录或所有民族技法 |
| 评价 | `check`、`audit-reference`、已知控制、等响度人工短样 | 分清技术、声学差异与听感方向 | 一个总分替代原曲理解或好听度 |

Orchidea可借鉴目标配器与约束搜索；本轮没有安装/跑其二进制。Apple Logic的Sampler、Articulation Sets和Stem Splitter可借鉴工作流，但不是跨宿主核心依赖，未购买/安装即不宣称拥有其音源。新分离器或可微模型只有任务、许可、硬件和真源控制适配后才接入，不因排行榜更高就换掉已跑通链路。

## 当前缺口应如何推进

v30独立主音已被用户否决。v31真实复杂源反例说明，当前两帧谱加自选包络本身丢失关键动态和双声道维度；**停止仅在同一路线改参数**。改读[参考创作路线选择](参考创作路线选择.md)，保留原乐团可编辑能力，以成熟本地参考条件音频作有界基准，和音色模型容量研究分别推进。只有匹配任务的真源控制才支持外推，简单同族控制不够；已解盲窗口也不能重新当未见集。

音色可信后，用独立新主题测试起音、连续推动、句尾和角色关系；在回乐团前先完成独立主音短样方向判断。不要把原曲转录换调称为新主题，不把参考轨迹重放称为可演奏音色，不在方向未核准时展开三分钟。

谱面上，声部叫`response`不等于听觉上有问答；可能是同时内声。检查它与主句的实际门值和发声重叠，但不把重叠一律视为错误。同样，避免全线机械加倍也不等于禁止风格需要的齐奏。

## 如何维护经验库

新增条目只在它改变决策时进入库：登记一手来源、所读范围、版本/日期、支持与不支持的结论、许可、项目证据。摘要或商品书目不能冒充全文；奖项只核案例身份。方法卡要写反例和验证动作，保持原文引用与项目推断分开。

先检索已有条目和项目`tasks/lessons.md`。同法两次实质修正仍不过，保留命令、输入、错误和已排除原因，再调查不同假设；不要只加更多相似论文、轨道或可调参数。保存旧卡与结果的版本/哈希，修正过的评价集不再是未见集。

方法库的结构检查和Agent前向使用测试只能证明可读取与行为路由；真实采样、音符、WAV、模型表现与人工音乐验收都需各自证据。
