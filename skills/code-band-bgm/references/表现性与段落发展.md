# 表现性、韵律与段落发展

适用：用户认为音乐太平、偏亮机械，或虽有多个声部却没有起伏。先保留用户认可的维度，分别检查图案、演奏、音色和发展，用户只需评价听感，不要求其命名乐器。

## 成熟方法的分工

- [GrooVAE官方方法](https://magenta.withgoogle.com/groovae)把击打图案与力度/微时序分开，模型可能补删击打，不保证保留输入鼓谱；两小节模型也不能负责整曲起伏。若需保骨架，先核实际hit差异，不能直接替换。权重、代码与数据许可分别登记。本项目已做单次官方JS CPU控制，观察到补删格；checkpoint单独完整授权未核准，因此不作通用默认依赖，也未将其输出用于本次作品。
- [Groove MIDI Dataset](https://magenta.withgoogle.com/datasets/groove)有带拍钟的人类鼓表现与明确CC BY 4.0许可。随附`assets/groove-profiles/`只保留一名鼓手一段110BPM hiphop闭镲的条件统计、来源与变更，不含完整MIDI图案；它不是原参考的节奏规律。
- [All-In-One](https://github.com/mir-aidj/all-in-one)可补拍点、强拍、功能边界和标签候选，不能给出配器、和声或主观情绪真值；其复杂可选环境在本机未实测，不自动安装。
- [MIDI-DDSP](https://github.com/magenta/midi-ddsp)将音符、表现控制和声音合成分层。借其控制思路，不声称现运行器实现了vibrato、持续亮度/音量自动化等全部控制；该项目未在本机运行，不替换当前音源。
- [GETMusic](https://github.com/microsoft/muzic/tree/main/getmusic)支持特定MIDI声部的条件生成，但官方说明GETScore不含音量信息。生成更多音轨不能省去表现与混音层；本项目未运行其权重。MusicAgent的模块化工具分工可借鉴，不能把其模型API配置作为宿主无关核心依赖。

实验研究也不支持“越多错拍越有律动”。[Senn等研究](https://doi.org/10.3389/fpsyg.2016.01487)中，量化与原演奏的groove评分可相近，夸大微时序会降低评分；[Witek等研究](https://doi.org/10.1371/journal.pone.0094446)支持特定鼓break中适中切分的作用，不能外推为本曲的最佳错拍量。保持可辨主脉冲，优先查角色配合与重音组织。

## 可执行的署名表现统计入口

```sh
python skills/code-band-bgm/scripts/band.py express \
  --score 父谱.json --part hats --out 新表现谱.json
```

可用`--profile 条件统计.json`显式指定同契约数据；默认是随附有来源的闭镲统计。常规渲染不自动应用该步骤，不下载模型、不加载TensorFlow或云服务。执行前需审来源，字段齐全和SHA不证明来源真实。

输出新谱、`.change.json`、`.groove-profile.json`。只改指定声部、16分网格上有至少3次观测的closed_hat；力度差限±8，期望时序限±5ms，并检查最终64帧调度差不超过6ms预算内的整块。未知拍位、其他鼓类、其他声部、音高、门长、ID与种子保持，不补删击打。段入口保起点，越界则保留原起点，仍需后续`validate/compile`核真实力度区域和同键门控。

这是一次**显式改写演奏起点**的定向操作，编译时仍按新的谱固定演奏；不是重新开启随机humanize。目标part须关闭随机humanize；当前仅支持恒速4/4、PPQ可整分四份，变速或其他拍号明确拒绝，不静默近似。不要反复对已处理谱再次叠加同统计。自定义profile须保留署名/许可/来源和变更，默认数据的许可见`assets/groove-profiles/来源与许可.md`；作品随附统计和署名。

统计重复本身仍会机械。跨小节强弱、减法连接、主从让位、动机发展和音区变化由宿主明确设计，不能把这一步叫“AI保证有灵气”。

## 真实音源是否执行了表现

先对同一短句做固定音高/起点的软硬力度控制。采样可能在当前力度内复用同一录样，合成器的VCA velocity sense可能为零；写了力度值不证明音色或音量改变。核实际波形、原生state、调制路由与各音响应，不信宿主缓存。修状态须另存新state、SHA与来源，保旧版。

区分note-on力度、自然包络和held-note内自动化。当前MIDI velocity只在起音作用；长弓/吹奏的持续渐强、CC11表情与真实legato没有实现时不得写进交付承诺。现有humanize.velocity为声部固定偏差，保证已有重音次序，不等逐音表现生成；需要句法强弱应写定音符力度和发音关系。

## 用一个短段验证发展

为本曲先写发展表：动机建立、延展/预备、释放、变奏回归、兑现/收束。顺序/长度是创作选择，不是所有曲子固定模板，也不是从能量曲线自动认出的原曲式。

可检查动作包括：一处和声跨bar延留与另一处较快变化；主线可辨动机保留及定向变尾；连接处允许低体/高频退而中体接管；两小节释放保另一层运动；仅峰段新增少量真实互补颜色，随后退场。不要所有声部一起mute再一起进，也不把全局增益起伏当全部发展。

每个新颜色解释职责、进入/退出、音区与实际发音。库存上百资源不等于上百独立物理乐器、奏法或全曲应同时演奏。已有某弦色的失败版本保留为反证，新增该音色本身不签音乐。

保存父版认可内容与未认可维度、逐音/角色变更、实际音源/state、音频检查、同响度对照及冻结重演。技术、素材/创作审查与人类听感分别记录；方向未通过不展开长曲。

## 持续推进与大型乐团的分工

前述发展表和“两小节释放”只是可选工具。用户要求维持推进、指出某段衰竭时，先查主句、和声、低音、打击细分是否同向退出；旧自定结构可以撤销。较低静态长音仍在演奏，不等它已经接过主曲。分开测音域、真实活动和谱中角色，不将能量/谱通量/音符数当情绪真值；低部增加而可听中层下降也会失去主曲感。可以保持节奏低盘，用动机展开、和声节奏、音区和音色接力继续发展，不必所有声部同时变弱来证明有起伏。

用户新增交响/大型乐队目标时，说明这是新的原创配器选择，参考原曲继续约束节奏或角色，不能假称原曲本就有弦铜管。按主句、回答、推进、和声/强调分配职责，再选可真实演奏的家族和具体音区。[伯恩斯坦1958年官方讲稿](https://leonardbernstein.com/lectures/television-scripts/young-peoples-concerts/what-is-orchestration)用里姆斯基作品展示几个独立想法如何分给不同乐器，也展示节奏盖住主题的坏配器；可借分工，不能复制名曲音符或把所有族全程齐叠当规模感。

新的弦/铜管须核真实采样区、力度和发音。合奏patch不等多人新录，attack加sustain两个zone不等RR或两位乐手；高区的低音提琴音色可能实际切到大提琴样本。选定低/中/高的职责、进入退出和不同发音，控制铜管的持续活动，让前景留有空间。没有CC11/真实连奏/弓法控制时，逐音力度和普通门控不能宣称等同持续表情自动化。

先一份短技术材料确认角色实际发声、同一增益口径和组合参与，再写完整短样。小组合没有鼓/低音时，不证明全混不掩蔽；不同时间窗的RMS也不能直接排名响度。完整短样需核用户指出的那段是否有实际主句/接句与和声/推进持续参与，保留仍未解决的平衡与人工听感。瞬间齐奏可以是表现手段，整段全部forte则需要具体音乐理由。

## 乐团必须实际承担主奏

家族已接入但仍被反馈单薄时，先查每族实际写出的是完整主题、对句、和声、推进还是少量点缀。鼓的多个资源分路不等同多个旋律层。全长RMS会受稀疏进入影响；比较已起音的同窗与后体，并核主题究竟由谁演奏，不从未入窗认弱，也不把多个有声part当大型乐团已通过。

可以将自有主题按乐句迁移给弦/铜管，原前景让位成内声或选位攻击色彩；记录每个迁移音的源ID、时间/音高/时值及必要的乐器适配。不要把钢琴短衰减的原gate直接叫弦乐连奏，也不把全线复制当作新对位。中域和声要有独立进行，低部与高部按职责留间距，推进层与主句用音区/发音区分。

[Belkin作者配器讲义（2015）](https://alanbelkinmusic.com/PDF/BelkinOrchestrationTheory.pdf)区分厚度与响度，并讨论族间接续平衡：铜管后突然转到较薄声部会产生落差。可在交接处保选择性目标加倍/和声延留，随后让出前景；不能在没有持续动态功能时宣称实现真实渐弱。全族共享和声时采用不同排列和声部进行，强齐奏只用于有理由的落点。以上是写作方法，不能直接签收成品的震撼或情绪。

主奏新音区/力度必须重新查真实采样区。完整短样中核迁移/和声活动、同成品增益口径、鼓低音骨架和交接段，保父文件及精确变更；同响度听感通过后再展开长曲。音源普通门控与真实legato、逐音力度与CC11、合奏patch与现场人数分别报告。

## 配器改善后主题仍不吸引人

主题由钢琴迁弦/铜管、延长时值或改善音域，只说明呈现改变，不等旋律已经更动听。用户继续否决时允许明确撤旧主题，先写一个短而可辨的自有动机，再安排相同节奏/核心音的回认、变尾、回答和唯一高目标；不要每句都换全新音型，也不机械全曲复制一格。整句用同一主族保持身份，辅助家族用独立呼应与有限目标加倍；不把逐音换色当层次。

[DeSantis的Ableton官方旋律轮廓章节](https://makingmusic.ableton.com/creating-melodies-1-contour)可用于平衡上行/回落、级进/跳进与峰目标，但不是保证上头的公式。先写精确新主题表，再对真实音源时值/音区和当前和声核适配；少音不自动等记忆性强，更多重复也可能乏味。保留参考的抽象pocket约束，不复用参考转录，音乐好听/情绪与风格仍需同响度短样人工验收。
## 明确乐句计划的确定性修改

`phrase`根据宿主明确指定的音符与职责关系，按相同计划修改各声部起音和力度；它不自动写旋律，也不保证听感。先从可编辑谱选择乐句内音符ID，保存JSON计划：

```json
{"schema_version":"1.0.0","start_tick":0,"end_tick":7680,"edits":[{"part_id":"lead","note_ids":["n1"],"offset_ticks":12,"velocity_delta":2}]}
```

执行 `python scripts/band.py phrase --score 原谱.json --plan 乐句计划.json --strength 1 --out 新谱.json`，输出新谱及`新谱.json.change.json`，渲染时可用`--change`保存父谱关联。多个声部可分别写入计划；相同offset是显式同步而非随机同步。强度零保持原谱对象；目标声部须关闭随机humanize，目标音符须完整位于指定范围内，超界、碰撞和非法力度会失败。该命令不改音高、音符时值、总长度或混音；变速与64帧量化可能影响实际门长，超出限制则拒绝。之后仍须编译、渲染和人工听感判断；持续音内部表情需使用下述渲染控制。

随技能提供的[乐句表现计划](../assets/示例/乐句表现计划.json)对应[五秒钢琴谱](../assets/示例/五秒钢琴.json)，供本地运行接口检查；它不是用户参考曲。

## 持续音控制

原生采样渲染可通过 `render --control-events 控制事件.json` 接受显式帧级CC11音量表情；文件为事件数组，示例见[持音控制事件](../assets/示例/持音控制事件.json)。每项为 `event_id`、`part_id`、`frame`、`controller`（目前仅11）和`value`（0—127），帧必须在总时长内且对齐64帧。事件随`events.json`保存，以`render --events 作品/events.json`可冻结复演；已含控制事件时不能再传另一个控制文件。当前不支持循环中使用控制事件；插件路径也不支持。未提供时维持旧行为。

实际效果取决于所选音色：已对真实弦乐预设验证CC11会改变持续音量，不据此宣称真实换弓或音色变化。步进控制可能产生听感突变，使用密集曲线前须核音频并留意帧网格。正式作品仍需检查音乐平衡和听感。
