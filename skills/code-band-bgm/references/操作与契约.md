# 操作与契约

需要 Python 3.10以上、NumPy、SciPy、jsonschema、soundfile、FFmpeg/FFprobe及libfluidsynth。Python依赖见技能根目录requirements.txt；音色库与许可随assets/soundfonts提供。核心不需要MCP、模型密钥、云服务或音频设备。其他系统按自己的包管理器安装FluidSynth，并用doctor验证，不能由macOS实测推断跨系统通过。

先在项目建立虚拟环境，避免不同宿主的python3指向不同解释器：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r skills/code-band-bgm/requirements.txt
```

本项目已实际完成此安装；后续命令优先用`.venv/bin/python`替换下方python3。Windows虚拟环境入口为`.venv/Scripts/python.exe`，该系统未实测。macOS本轮通过Homebrew安装`fluid-synth`，系统同时需`ffmpeg`。安装系统包会带入包管理器自己的依赖，安装器不会替换或删除用户现有规则。

从项目根目录运行（在其他目录时将入口换为实际技能根路径；Agent调用应使用参数数组）：

```bash
python3 skills/code-band-bgm/scripts/band.py doctor --out reports/新能力.json
python3 skills/code-band-bgm/scripts/band.py doctor --soundfont-packs skills/code-band-bgm/assets/soundfont-packs.json --out reports/含扩展音色能力.json
python3 skills/code-band-bgm/scripts/band.py catalog --query 古筝 --capabilities reports/含扩展音色能力.json
python3 skills/code-band-bgm/scripts/band.py analyze --input 本地参考.mp3 --out work/参考分析.json
python3 skills/code-band-bgm/scripts/band.py audit-reference --reference 本地参考.mp3 --candidate 候选.wav --seconds 20 --out work/新声学对照.json
python3 skills/code-band-bgm/scripts/band.py validate --score work/乐谱.json
python3 skills/code-band-bgm/scripts/band.py compile --score work/乐谱.json --capabilities reports/新能力.json --out work/事件.json
python3 skills/code-band-bgm/scripts/band.py render --score work/乐谱.json --capabilities reports/新能力.json --out outputs/作品/v1
python3 skills/code-band-bgm/scripts/band.py check --input outputs/作品/v1/final.wav --expected outputs/作品/v1/score.json
python3 skills/code-band-bgm/scripts/band.py revise --score outputs/作品/v1/score.json --part drums --gain-db -4 --preserve melody --out work/修改乐谱.json
python3 skills/code-band-bgm/scripts/band.py render --score work/修改乐谱.json --capabilities reports/新能力.json --change work/修改乐谱.json.change.json --out outputs/作品/v2
python3 skills/code-band-bgm/scripts/band.py render --score outputs/作品/v1/score.json --events outputs/作品/v1/events.json --capabilities reports/新能力.json --out outputs/作品/复现
```

以上是已实现入口；示例路径需要换成实际文件，不能将命令展示视为执行通过。每条命令输出JSON，成功退出码0，输入/能力/测量失败退出码2。输出已存在时拒绝覆盖，需使用新路径。不要把需求文字、文件名或URL拼成shell代码。

参考音乐的本地声音描述用 `describe --input 本地音频 --model 本地模型目录 --out 新报告.json`，需要单独的可选环境，见[本地音频理解](本地音频理解.md)。无参考的一句话作曲直接由宿主编排，不强制加载音频语言模型。`analyze`成功只表示数值测量完成；首次参考渲染还需[参考证据契约](参考与许可.md)。

局部多乐器音符候选用`analyze-notes --input 本地音频 --model-config 本地资产配置.json --backend-python 隔离环境/bin/python --seconds 8 --prefix-seconds 0.25 --out 新目录`。固定资产登记、实际环境及候选/边界限制见[本地音符与动态分析](本地音符与动态分析.md)。命令成功不等于原配器/和弦识别成功，不能用参考notes直接生成所谓原创曲。

## 多音色库登记

中国音色原型作为独立SoundFont接入，基础SF3不改。`assets/soundfont-packs.json`登记每库的路径、内容摘要、许可文件、来源和真实预设。路径相对登记文件解析；运行时路径不进入乐谱或冻结事件。新增外部库不能只加名称，必须取得真实文件和许可、登记SHA、完成 `doctor`发声及区域检查。

编译和渲染同样传 `--soundfont-packs skills/code-band-bgm/assets/soundfont-packs.json`。遗漏、错文件、区域不存在均失败，不静默换主库同bank/program。多库事件保留实际使用的资产SHA列表；重演仍需同一登记和资产。既有单库两参数引擎接口与冻结文档保持兼容。

已完整探测主库后，只增加独立扩展时可运行：

```bash
python3 skills/code-band-bgm/scripts/band.py doctor --reuse-capabilities reports/基础能力.json --soundfont-packs skills/code-band-bgm/assets/soundfont-packs.json --out reports/扩展能力.json
```

这会核实基础能力与旁边的`.probe.json`一致、引擎版本和主库SHA未变，明确复用原发声证据，只对新增库实测；不冒称重跑全部基础预设。

首次完整`doctor`还会对主库各鼓组的GM35—81逐键清声实测。复用旧的十键报告而需要开放完整标准打击时，追加`--verify-percussion`。只登记实测通过的键；本机八组共376窗口中373通过，808组58/65/66未通过并明确排除。标准鼓组47键全部通过，可用于铃鼓、康加、邦戈、牛铃、卡巴萨、响棒、刮瓜、天巴、三角铁、库伊卡等基础采样；名称和键位不能保证完整奏法或文化真实性。

## 数据责任

- Agent把需求写入intent、把实际作曲写入sections与parts，不是靠程序解析关键词随机填音符。
- JSON Schema只约束结构。运行器另检查唯一ID、速度表、拍号变化、段落连续覆盖、门控、参考模式、尾音预算、音色/演奏法绑定和输出能力。
- 四分音符以PPQ计tick；BPM是分数，每个绝对位置用有理数累计，再四舍五入到帧（半帧向远离零方向）。6/8不自动改变BPM单位。
- 当前FluidSynth内部块64帧，起止最后量化到最近64帧，最多32帧误差（48kHz约0.667毫秒）。事件记录时序随机偏移与量化偏移。编译后事件是当前引擎真值，不能再重新抽人性化。
- 声部资源绑定到engine_id/capability_id/instrument_id/mapping_version。音色库整文件SHA-256、FluidSynth版本、预设bank/program固定。内部样本选择由SoundFont键域/力度层决定；没有可控轮换，不把重叠采样层称为轮换。不支持的显式采样选择不会静默忽略。
- 固定种子使用SHA-256计数器，时序与力度命名空间独立。当前力度以声部共同小偏差保持谱面重音关系；时序按同起音组共享偏移。段落首拍和锁定音符不加随机起音漂移。混音增益变化不影响演奏事件。
- 当前支持普通演奏法、整数半音、声部增益/立体声平衡、选定混响，以及经能力探测的原生chorus、有限延迟和显式duck，参数与限制见[延迟与空间](延迟与空间.md)。混响/chorus的`target_part_ids`空列表作用于全体，非空只作用于指定真实声部；低音与鼓可保持干声。不支持的效果、微分音、逐音符声像、同声部同音高重叠、独立样本轮换和分轨导出明确拒绝。SF3采样压缩帧数未知，与最终WAV可精确读帧是两件事。

## 尾音与循环

普通输出：主体帧数加append尾音帧数必须等于最终目标；淡出占已有尾部，不增加总时长。先在作曲时预留尾音，不由渲染器强行补长或截断门控。

循环输出：当前实现使用连续三个周期预热，保留第三周期，效果状态进入开头。周期必须是64帧整数倍，tail_policy为wrap_into_loop，end_fade_frames为0。原契约的tail_wrap_crossfade可用crossfade_frames=0表示零交叠，此处采用连续周期状态衔接，明确不实施交叉淡化；诊断记录crossfade_applied=false。三周期预热是否充分须结合音色释音和混响衰减测量，不能只凭预热次数宣称无缝。

输出附三周期试听文件和首尾跃变测量。没有人工试听/阈值校准时，循环文件可交付为候选，接缝听感保持待验收。

原生chorus、有限延迟及duck各自的循环状态未验收，包含这些效果的循环谱明确拒绝；不能因基础混响路径可循环而推断新增效果也可用。

## 失败与恢复

正式成品先在同目录临时工作区渲染并检查，通过后整体发布新版本。失败临时目录保留失败记录，不属于成品。结构示例、pending音色、未知能力、格式不支持、错版本、缺资源或已存在输出路径均返回错误，不生成假成功清单。

manifest记录实际参数数组、版本、种子、乐谱和资产摘要、最终文件与解码数据摘要。复现要求固定乐谱、能力文件、已解析事件、引擎版本、库文件和设置；跨平台浮点一致性未保证。作品版本目录名承担版本，score_id保持以免混音修改重抽随机流。

新增有限抽头延迟的参数、路由、尾音与循环限制见[延迟与空间](延迟与空间.md)。新增能力须使用本轮doctor实际生成的报告；旧无延迟作品的固定事件可保持原能力重演。


## 可选的单插件声部

本公开版 v1 不含插件合成器、采样与插件合奏、谱模型拆解和谐波音色构建（它们依赖 GPL 或 AGPL 的可选组件）。



可选CPU拍点已接同一`analyze`入口：`--rhythm-backend beat_this --rhythm-model 本地checkpoint --rhythm-model-sha256 期望摘要`。它惰性加载`requirements-beat-this.txt`所列独立依赖，5—600秒、CPU FP32、无DBN；模型不随命令下载，缺失或错摘要明确失败。原始拍点/强拍相对本次输入起点，不推断唯一BPM/拍号/鼓件；详见[拍感与角色核对](拍感与角色核对.md)。基础/librosa参数与默认路径保持，传给其他后端的模型参数会被拒绝。
