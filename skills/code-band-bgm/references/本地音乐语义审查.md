# 固定窗口本地音乐语义审查

`review-reference`把本地音乐模型执行、结构校验与音乐主张分开。它不上传音频、不自动下载，不把模型回答自动写成已核准参考，不放行新曲。普通文字创作、采样和插件渲染均不依赖此后端。

## 实现与适用条件

可选适配器复用[MIT MLX-Audio的MOSS实现](https://github.com/Blaizzy/mlx-audio/tree/7a0986280fe295f4cf40f64164bb23abed416a22/mlx_audio/stt/models/moss_music)，明确指定`strict=True`。模型权重许可另核，不能从MIT代码推出模型授权。模型目录不准入Python源码或符号链接，标准分词器不可配置动态`auto_map`。原OpenMOSS仓库/旧PR的Python源码未复制进核心。

当前只实测24GiB内存的Apple Silicon；隔离环境实际版本为mlx0.32.4、mlx-audio0.6.3、Transformers5.22.1、NumPy2.5.4、soundfile0.14.0。MLX内存分配上限14GiB，包含加载/预处理/生成的整个子进程上限240秒；这些不是整机总内存保证。需要约10GB模型和相应运行内存，普通渲染不安装这套依赖。Linux/Windows、低内存机器、其他精度、原生BF16和跨硬件确定性未实测。

## 封存与运行

先按操作者适用的许可取得并核查一个固定版本的本地模型；本入口不承担下载。命令中的目录由当前宿主定位，相对模型路径按配置文件位置解析。

```sh
隔离环境/bin/python 技能目录/scripts/moss_review_backend.py \
  --register-model 本地模型目录 \
  --expected-sha256 已核实的64位权重摘要 \
  --out 新的后端配置.json

渲染环境/bin/python 技能目录/scripts/band.py review-reference \
  --input 本地参考.wav --start 60 --seconds 8 \
  --model-config 后端配置.json \
  --backend-python 隔离环境/bin/python \
  --out 新的候选审查目录
```

登记同时封存全部模型文件（含config/tokenizer）、已装MLX-Audio全部Python源码（含其内置语言模型）、五项依赖版本。运行前复核内容与文件集合；版本/源码变化应先重新审查，用新配置，不改旧摘要。保留虚拟环境解释器路径，不将它解析成环境外的系统Python。

`--task roles`为默认，仅收集声音大类、前景发声、节奏低音、层间配合、最多两条竞争解释和未知。`--task control`用于匿名已知控制，包括静音；roles会拒绝静音，但这不能算模型正确认识静音。窗口0.5至30秒，16k单声道FLOAT中间输入精确帧数；不擅自改响度。需要等响度对照时先另存并记录常数增益/实际测量。预算默认768，允许256至1024；达到预算、空输出、非法JSON或错误字段不算成功。

## 输出与边界

- `input.wav`：实际送入模型的固定窗；源文件SHA、窗口起点和帧数在`review.json`。
- `model_result.json`：模型原始文本、单独剥离后的最终文本、生成计数、提示词、版本、严格键形检查、同次generate内部processor/encoder trace。去掉think文本不表示关闭模型思考。
- `review.json`：只有`local_music_model_execution_and_structure`通过；主张仅为candidate/unknown，`ready_for_composition=false`。未知字段绝不变成肯定主张，整窗候选不是逐项时间定位。
- `backend.log`：实际子进程输出。失败保留临时研究目录与失败记录，不发布目标结果目录；禁止覆盖已有目录。

完整单个JSON围栏可无损解包；不从混合正文抽取片段、不修补、不补造空缺字段。模型返回全未知可通过结构校验，但没有提供可行动音乐解释。字面声源名称、精确音符/和弦/BPM与真实preset仍须独立证据。

部署后先按[参考理解验证](参考理解验证.md)做预先冻结的已知正负控，再评价参考。项目当前Thinking权重的实测失败包含静音幻觉和声部重叠关系错误；不能以接口真实执行覆盖这些结果。旧`describe`保留历史兼容，其泛描述也不能自动核准配器。音乐方向与人工听感另验，未解决时暂停新主题与长曲展开。
