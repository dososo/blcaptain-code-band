# 创作与修订流程

实际创作、参考拆解或定向修订时读取。本文件由原主入口完整迁移，相关契约仍以所链接资料和运行器为准；知识方法的选择见[音乐知识与决策](音乐知识与决策.md)。

本公开版 v1 不含插件合成器、采样与插件合奏、谱模型拆解和谐波音色构建（它们依赖 GPL 或 AGPL 的可选组件）。

由当前 Agent 理解音乐需求、创作主题和编排。通过本技能 `scripts/band.py` 执行稳定程序，不嵌入收费作曲模型，不为每首曲目重写渲染器。本地音频理解通过独立适配器补齐，不把外部上传作为必要步骤。命令中的技能根目录由宿主定位，不依赖当前工作目录或个人路径。先读[操作与契约](操作与契约.md)。

参考同风格创作目前仍是未通过音乐验收的能力：真实WAV/局部分析已运行，不能宣传可靠理解任意原曲。遇参考整体风格否决，先按[参考理解验证](参考理解验证.md)检查方法能否区分真实参考与有竞争力的错误实现；暂停新主题渲染和长曲展开。通用作曲理论、四维字段齐全或本地GM可演奏均不能补上这项验证。

1. 先检查项目已有进度与能力文件；优先使用项目虚拟环境的Python，先确认依赖可导入。首次运行 `doctor --soundfont-packs 技能目录/assets/soundfont-packs.json --out 新能力文件.json` 探测基础和随附扩展音色；未使用扩展库时可省略登记参数。用 `catalog --query 乐器名 --capabilities 能力文件.json` 查询真实资源及限制，详见[乐器目录](乐器目录.md)。只有真实存在的资源才能绑定；扩展库在编译、渲染时传入同一登记参数。这里是按演示机制新建的 FluidSynth 乐团，不能声称获得了原视频源码。能力变化后重测，同摘要同引擎的逐音色探测证据可复用。
2. 将一句话整理为简短中文简报；默认无人声、最终60秒（含尾音）、48kHz/24位/双声道。自行选择合理音乐参数并说明，避免参数问卷。有参考时先用 `analyze` 取得真实音频测量，读[参考与许可](参考与许可.md)。绑定用户具体目标与实际输入声轨；网页挂载music只属候选，没有同录音匹配时用实际视频音轨。以可靠证据核准音色质感、律动、和声密度与情绪结构；BPM/调性/能量或题目不足以单独确定风格。未实际听辨或证据不足时准确说明缺口，主动完成本地取证和对照，不自选另一种编制渲染后声称对应参考。有可靠证据或已有明确风格约定时直接继续，不逐阶段审批。
3. 宿主没有音频感知能力时，按[本地音乐语义审查](本地音乐语义审查.md)用`review-reference`取得固定窗原始回答、候选/未知和真实接线证据，先经匿名已知控制，再与`analyze`交叉核对。执行/结构通过不能自动登记参考理解核准；旧`describe`及其边界见[本地音频理解](本地音频理解.md)。缺依赖时说明安装步骤，不改走第三方上传，不把模型估计称为人工听辨。关键参考解释足够可靠或无参考时，依据能力和[音乐创作基线](音乐创作基线.md)写新主题、和声、段落及乐谱。核心乐谱遵循 `assets/schemas/乐谱.schema.json`。稳定ID和种子保持；按风格选择真实存在的乐器，不能把日本筝、长笛或日本太鼓改名冒充古筝、笛子或中国大鼓。
4. 需要辅助声音对照时读[本地风格对照](本地风格对照.md)，先用`audit-reference`比较真实固定窗口的频谱、包络与声场；需要嵌入对照时使用`compare-style`先做负对照校准；不得用相似度代替曲目身份或风格验收。用户否决后先检查参考解释是否成立；仅在关键解释已验证、问题已定位为局部实现时，才用同原创主题做一次短受控修正。整体方向未解决先回参考理解验证，不沿原配器/句法继续修补。不能只增加音色或换一段模型描述后重做长曲。空间及原生包络参数与边界见[延迟与空间](延迟与空间.md)。`validate` 后 `compile`。首次方向需要时只做一个15至30秒预览（独立片段乐谱），再 `render` 完整作品到新版本目录。检查失败时定位问题，同方法最多修复两轮。未生成的WAV不能交付。
5. 技术通过后交付 `final.wav`、乐谱、事件、简报、清单、检查和使用说明。明确“未试听，等待人工审核”；数字峰值、真峰值、响度和人工接受分别记录。不得宣称保证完全原创或全风格通用。

修改时先读取父版本。对“鼓轻一点、保留旋律”可用 `revise` 修改鼓声部增益并完整保留旋律声部，再渲染；核验事件差异。缩短或加弦乐由 Agent 精准编辑乐谱，保持不受影响的ID，保存父哈希及变更记录。循环需满足实际实现的周期状态方法、精确帧数和接缝证据；不能以补静音、普通淡出冒充无缝。

参考拍感、角色不清或连续风格否决时，先读[参考编配拆解](参考编配拆解.md)，按需读[拍感与角色核对](拍感与角色核对.md)。先解释鼓、低音、和声节奏与前景层怎样配合，再决定真实音色组合；单音探针、不同音色有反差或来源字段齐全不证明参考编配已理解。可选`analyze --rhythm-backend beat_this`使用显式本地模型和SHA做CPU拍点，不自动下载；漏拍/半倍拍不直接签收唯一速度。用户情绪目标优先于模型标签，音色候选、创作选择与原曲事实分开；诊断性试奏不升级为风格通过，连续失配暂停同法猜改，不展开长曲。

需要局部复音候选时按[本地音符与动态分析](本地音符与动态分析.md)使用`analyze-notes`，显式指定已登记的本地YourMT3资产与隔离Python。它保留原始解码、边界删失和错误，不把program当原乐器、不将参考音符直接用于新主题。低音让位可用已探测的显式`duck`事件包络，见[延迟与空间](延迟与空间.md)；这是自有制作选择，不代表识别了原曲压缩器。

用户指出单薄、不舒展或缺旋律/层次时，读[乐句与层次编排](乐句与层次编排.md)。先核实际长短音、非尾音呼吸、动机重现、辅助声部和内部进退，再选必要音色；连续有调主体不等于所有音全程持续，延长gate也不保证真实采样延续。先一个短样，不以轨数、理论符合或指标签收音乐。

方向已有部分认可而仍缺连续推动时，按同文的“连续推动与接力”核绝对门控帧、真实释放、全混边界和错相负控；目标长音、内声退让与回答交叠逐项入谱。先保认可骨架，不为推动猜加原曲音符，不将声部诊断中的原生master重复计入。

宿主适配与移除见[宿主安装](宿主安装.md)。纯聊天客户端没有本地执行器时只能提供指导，不能宣称已独立生成WAV。

需把接线、量化和模型任务能力分开核查，或实际取得六源估计与四角色证据时，读[本地分离与角色证据](本地分离与角色证据.md)。`separate-reference`复用显式本地Demucs；轨名不等原乐器。可信局部观察可用`local_role_analysis`证据包进入既有渲染门禁，无需不稳定caption盖章；摘要/结构通过仍不签收音乐。原生chorus只在同资源受控试奏支持表达需求时使用，不凭某句模型描述换乐器。

参考包含乐队合奏、多层次/情绪/空间变化或间奏时，读[合奏与段落分析](合奏与段落分析.md)。按真实变化选多窗，分开估计源类别、乐器家族候选、演奏职责与段落交接；`analyze-instruments`可用显式本地PANNs输出完整多标签候选，不能取top1认琴、以分数当概率或将527音频类别说成527种乐器。一个分离类别可含多源，不得反推只能用单一音色；允许有职责、有真实来源的多承载编配。新作情绪目标与原曲情绪假说分开，低能量不自动标忧郁；保留残差、误标签和未观察区间，实际短样听感仍另验。

被指出单薄或单一时，先比较原mix与失败实现的分频空间、打击活动分布、持续载体与短击关系；同窗总宽度、每击衰减或谱峰数不能单独裁决。选择复音插件须用完整state与真实同时音控制核准当前patch；不要只信宿主缓存的Poly文字。将支持的关系落实到具体音源/音区/事件/效果路由，做一次受控短样，保留仍未缩小的差距。

鼓点仍缺重量时，按[参考编配拆解](参考编配拆解.md)核起音/鼓身/尾窗和真实源相加；叠加抵消时可选位替换，检查多底鼓与持续低音的实际触发并集。多音域需求先核内声活动与共同音分工，不凭乐器数或候选预设增加常驻层。

被指出太平、机械、缺起伏或情绪时，读[表现性与段落发展](表现性与段落发展.md)。保留已认可维度，查跨bar角色/和声节奏及真实力度响应；可显式用`express`对指定闭镲应用署名条件统计，不自动下载或运行模型。统计不是原曲规律，错拍和轨数不签人味；逐音表现、自然包络、尚未实现的持续自动化必须分开。

用户报告爆破/点击时，先读[延迟与空间](延迟与空间.md)末“因果定位”：核真实帧/声源叠加、原WAV与试听副本，不把无满幅等同无爆音，不盲给全曲去click。配器已改善而主题仍不吸引人时，按[表现性与段落发展](表现性与段落发展.md)明确重写短动机及回认/发展，不继续把换主奏当作曲改善。

用户说“乐团有了但不会组合”或指出持续尖亮声时，按[参考编配拆解](参考编配拆解.md)末节先做同窗同gain的真实源消融，必要时取得听感定位。定位不等删除处方；先保主旋律/推进功能，隔离音色、包络和混合问题，不能把静音负控或小白观察直接变成删主奏/重编配。原参考乐器未知、新作问题源已定位和新编配通过分别记录。
